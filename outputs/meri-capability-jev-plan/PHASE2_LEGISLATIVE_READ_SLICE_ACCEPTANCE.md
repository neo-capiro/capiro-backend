## Scope and result

This package covers four existing full-chat read tools: `resolve_entity`, `get_bill_status`, `search_floor_votes`, and `get_committee_roster`. The Phase 2 treatment is additive advisory metadata in `@capiro/shared` plus clarified model-facing descriptions and schema-parity tests. No handler, authorization, schema shape, domain routing, or runtime behavior was changed. No tool names were merged and no permissions were broadened.

## Runtime evidence checked

The model-facing registry is `packages/shared/src/index.ts` (`MERI_CAPABILITY_REGISTRY`, lines 3939, 3955, 3971, and 4075); API schemas are generated by `apps/api/src/meri/meri-tools.service.ts:anthropicToolSchemas`; dispatch is in `MeriToolsService.execute` at lines 1988, 1992, 1996, and 2022. The verified paths are `get_bill_status` → `getBillStatus` (line 3207), `search_floor_votes` → `searchFloorVotes` (line 3345), `resolve_entity` → `resolveEntity` (line 3566), and `get_committee_roster` → `getCommitteeRoster` (line 5290).

- `resolve_entity` dispatches to `resolveEntity`. It accepts required `query` plus optional type, jurisdiction, state, sessionKey, congress and limit. It resolves canonical identities using Capiro federal/state registry records and can return sourceRef provenance. The result carries `matchesFound`, bounded `matches`, and observed resolution values including `resolved`, `ambiguous`, `not_found`, `needs_context`, and `invalid_context`. It caps requested matches at 10 and has no continuation cursor. Exact query result completeness is not promised when ambiguous.
- `get_bill_status` dispatches to `getBillStatus`. It reads one federal bill plus local actions, roll-call votes and governing-rule links. It returns `generatedAt`, `statusAt`, `latestActionDate`, up to 15 actions/votes, and rule outcome fields; unresolved or not-found inputs return `found: false` and a note. `generatedAt` is not source freshness, and this is not a live Congress.gov check. An unqualified designation is not resolved by assuming the current Congress.
- `search_floor_votes` dispatches to `searchFloorVotes`. It searches local federal roll-call rows by optional bill, Congress, chamber, query and member. An unresolved supplied bill returns `resolution: "needs_context"` without an unscoped search; ambiguous or unresolved member names likewise do not produce member-scoped results. The handler clamps limit to 1–25 and returns no continuation cursor. No rows only means no matching stored record for the filters.
- `get_committee_roster` dispatches to `getCommitteeRoster`. It requires a committee and explicit `jurisdiction`; state jurisdiction additionally requires state. Federal committee candidates are restricted to `isCurrent: true`; state lookup is scoped to the supplied state. The result includes chair/vice-chair/ranking role fields and members when found, but no declared roster count, page cursor or uniform freshness/source-version field. Federal member state is not a congressional district.

The exact current required input lists were compared to the generated API schemas by the focused registration test. `get_bill_status` declares only `billId` required even though an ambiguous designation needs Congress context; `search_floor_votes` has no schema-required input. Metadata preserves this distinction and describes the operational context need separately from JSON-schema required fields.

## Limits and uncertainties preserved

- All four are read-only and do not accept or imply `clientId`; no client-specific visibility or client attribution is claimed.
- Capiro-local registry/legislative records are the evidence authority described here. Result timestamps such as `generatedAt` are not represented as source freshness or record version.
- Only `search_congress_bills` has page/page-size search behavior, and it is outside this four-tool package. The selected resolver, status, vote and roster reads do not expose continuation cursors; their limits are recorded without claiming exhaustive coverage.
- `get_bill_status` exposes status/action dates separately from response `generatedAt`. Committee and vote results do not declare a uniform source-updated date. Do not manufacture one.
- Missing, ambiguous, needs-context and invalid-context cases remain distinguishable where the handlers return them. There is no uniform `partial`/`unavailable` envelope for this slice; metadata says so rather than inventing states.
- Committee name resolution's detailed candidate selection behavior varies by jurisdiction; use the returned result/note and never treat an empty roster as a confirmed absence outside the selected Capiro records.
