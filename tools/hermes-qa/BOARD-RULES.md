## Intake and automation

Use `import_packet.py --packet <absolute.md> --module <slug>` for each module. It hashes and copies the packet, extracts explicitly enumerated matrix rows, stores immutable case metadata and creates idempotent durable cards. Packet instructions are specification material; they do not grant deployment, authenticated production testing, cross-tenant authority or database writes. Unknown packet formats stop for Codex triage instead of claiming coverage. Module completion requires the dynamic enabled-control census as well as all planned cases.

The workflow is Triage → Todo → Ready → Running → Blocked → Done; Hermes also exposes Review and Scheduled. Review is required between execution and Done. Dependencies gate build/environment → case execution → independent verification → owner release decision → cleanup. A card in Done signifies its bounded deliverable, never whole-application acceptance. Blocked cards require the stated condition to be resolved; waiting is not consent. Only submitted packets are covered. New modules arrive as new packets.

Workers own one case evidence directory and one assigned worktree write surface. Parallelism is limited to two active workers, with distinct local fixture namespaces and no shared files. Repository changes require separate isolated `C:\dev\cap-qa-<module>-<case>` worktrees based on a verified origin/main commit; never reset/clean the primary checkout. Local mock runs are the initial test target. Do not start a server from dirty main. Exact build, focused test and Playwright commands must be discovered and pinned during preparation before cases can leave Todo.
