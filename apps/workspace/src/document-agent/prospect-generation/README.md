# Prospect generation

The saved prospect document supplies an exact atomic-save version, an explicit section selection, and a writing brief. Core verifies current prospect, editor and client-wall access through the shared source resolver. This flow never fabricates Document Agent phase approvals.

The existing WsAgentProposal row retains the request before external work. The existing Core bootstrap ledger registers its deterministic native conversation; the existing native conversation owner executes the paid turn. The optional writing brief travels separately from quoted source snapshots. Only the original actor may retry or reconcile generation, using the same native request identity. Reads never start a new model run. Authority is checked again before retaining a result.

A ready proposal can be explicitly accepted or rejected by a current editor. Acceptance uses the canonical atomic draft save to commit proposal status, content, provenance and the immutable saved version together. A stale base cannot overwrite later work. The decision request UUID identifies its exact saved receipt, including after subsequent edits. Publication remains the separate existing publication operation.

No new tables, queues, approval owner, model loop or browser authority are introduced. Bootstrap uses the existing API_BASE_URL and service-secret configuration; native execution uses the existing generation client. A deployment must include the Core278 source-binding migration and the native leaf's optional document writing-brief transport. Local checks use synthetic PostgreSQL and stub external model/bootstrap calls; no provider execution or deployment is claimed.
