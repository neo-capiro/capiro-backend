# Planner subtask and view controls

The twenty-fourth release adds dense subtask controls and Strategies-backed personal view layouts. Full Asana Work parity remains open. It uses existing Planner resources with no schema migration, shared authentication change or additional Capiro integration.

Task-detail subtasks have hide-completed, assignee and inclusive due-date filters, sorting and reset controls. Loading waits for every authorized child page; inverted date ranges show an error. Completion uses each child’s current permission and opening version. New UI subtasks begin unassigned and explicitly independent of project membership and dates. Live qualification caught and corrected a legacy API fallback that ignored an explicitly empty membership list. Callers that omit the membership field retain the earlier compatibility behavior; explicit lists are now honored without widening task access.

List supports first-level expand/collapse while preserving deeper expansion choices, plus individual/all group collapse. Explicitly grouped descendants retain their own group row without repeating under an expanded parent elsewhere; time totals remain distinct. Board columns preserve collapse state and remain drop targets. Timeline/Gantt display first-level project-member descendants only, and provide an unscheduled panel with a persisted show/hide choice.

Personal layouts belong to the signed-in member, organization, project and view. Strategies rechecks current project visibility and captured versions, rejects duplicate active preferences including conflicting restore, and excludes every other owner, including organization admins. Pending saves suppress duplicate clicks; delayed results from a previous organization/view cannot replace the current scope. Reset recoverably archives the personal preference and restores defaults. Opaque saved task identities confer no task access. These controls do not write tasks, time, comments or notifications.
