# Planner branching forms

Implementation qualified locally; production promotion and signed-in checks are pending. This release remains part of the active Asana work-parity goal.

The Planner form builder supports short/long text, email, dates, numbers, single/multiple choices, and attachment questions. Questions have descriptions, required flags, text limits, ordering and up to five levels of branches driven by earlier choice answers. Current project fields can receive mapped responses; field types/options and task sections are rechecked at both save and submission. A selected non-file question supplies the task title, falling back to the form name when empty or hidden. Chosen titles are bounded to 500 characters; full description answers are retained. Settings include task section, assignment/status/priority/estimate defaults, copied visible answers, confirmation text, another response, signed-in submitter collaboration and signed-in/public-link access. Preview responses never create tasks. Duplicates have fresh question identities and remapped title/branch references; public capabilities are not copied.

New forms default to signed-in access. Signed-in submission follows current project access, including viewers; anonymous requests require an explicitly published, revocable capability. Changing access to signed-in clears its capability. Public responses contain questions and confirmation settings only, without project custom-field IDs, mapping targets, default assignees or task contents. Legacy forms and JSON submissions remain supported.

Attachments are ordinary private Planner task files, with no Workspace integration. Multipart input accepts at most ten files and 25 MB in aggregate; memory is bounded while bytes arrive, including hidden or invalid uploads. Required/single-file rules use actual received files. Hidden branch answers/files are excluded; the server independently validates visibility. A capability guard rejects unavailable links before buffering. Uploads use only the existing tenant/task S3 prefix. Preflight validates fields, access, defaults and required answers before S3 writes; the final tenant transaction rechecks the current form version, membership, project fields and public capability. Task creation, attachment metadata and activity commit together. Failed/uncertain uploads receive best-effort S3 cleanup; a cleanup failure is logged without private filenames or answers. The existing durable per-form quota remains ten submissions per minute.

No database migration, authentication change, IAM, Compute/CDK, canonical API or routing deployment is required. The seven-migration/eight-table production baseline remains in place. Only immutable Strategies and web-vNext images/release identifiers may change.
