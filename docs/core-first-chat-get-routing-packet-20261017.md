## Exact listener delta

Move the **same** independently retained, host-only fixed JSON 404 rule from priority 3 to 4. Its host remains `first-chat-preview.app-dev.capiro.ai`, response remains `404` / `application/json` / `{"error":"PREVIEW_ROUTE_NOT_FOUND"}`, both deletion and update-replacement policies remain `Retain`, and its exported physical rule ARN remains `Capiro-Preview-First-Chat-Core-Guard-RuleArn`. A replacement or second guard is a stop condition.

The new priority-3 rule forwards only host `first-chat-preview.app-dev.capiro.ai`, method `GET`, and exactly these anchored ALB path regex values to the existing held Core target group:

```text
^/api/me$
^/api/clients$
^/api/clients/[0-9a-f]{8}-[0-9a-f]{4}-[1-5][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$
```

One host, three path regexes and one method use five rule evaluations. There is no `/api/clients/*`, conversation history, GET `/health`, or new POST rule. The ALB matches the URL path independently of the query string; the frontend's closed optional client query and Core's own validation remain necessary. Public `/health` and every unlisted request on this host must still hit the fixed 404 guard before any production listener rule. Target health uses the *private* unprefixed `/health` on port 4000. The reviewed frontend read gateway sends the Clerk `capiro` template token to these ordinary Core GET routes and applies its own private/no-store response policy; conversation history and native Core authority POSTs use the native session token. The ordinary PR48 GET middleware can create or rebind a user, self-heal membership, update `user.lastSeenAt`, and audit denials; it does not perform the native POST authority route's online `sid` session recheck. The direct client detail route can return an archived client in the same tenant. These exact existing semantics require explicit acceptance or a separately qualified Core source/image correction before exposing GET3; native POST identity proof does not close them.
