### Pending product decision — not an implemented or accepted bridge

Existing history establishes separate Core brief versions and Workspace drafts, immutable prospect origin, current linked-client access and owner/collaborator rights. It establishes no Core-to-Workspace copying, automatic syncing or writeback. The viable behaviors are:

1. An explicit, independent editable Workspace copy pinned to one selected saved Core brief version. The source tuple must retain exact prospect/brief/version identity and returned sections/snapshot hashes; destination identity is exact Workspace draft/document. Source and destination owners must revalidate current access. Workspace edits create only Workspace history; the Core version remains unchanged. This is the recommended minimal behavior, **pending Neo's decision**.
2. Workspace as an editor of the Core brief, where saves also create a new Core brief version. This needs a reviewed mapping from rich blocks to Core's five text/citation sections plus coordinated conflict/replay/writeback behavior. Existing source does not define it; it cannot be inferred from a link or template.

Historical source versions are selected deliberately and re-read through the current Core owner; a newer Core current version must not silently rebind the selected version. Request IDs, hashes and saved links do not replace current authority. The pending choice does not delay the independent regulatory range feed. No source-association payload, route or mutation is implemented until that choice is confirmed.
