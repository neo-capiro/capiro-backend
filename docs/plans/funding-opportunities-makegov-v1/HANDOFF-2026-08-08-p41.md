## Traps hit this session, so the next agent doesn't re-hit them

- **A midnight test fixture can hide a real date-arithmetic bug.** Part 1's
  first pass differenced raw instants instead of calendar days; every test
  passed because `asOf` was exactly `T00:00:00.000Z`, the one clock value that
  makes the bug invisible. Caught in self-review, not by the tests. Any new
  date comparison in this file needs a mid-day `asOf` in its test.
- **Rendering a null fallback in only one branch of a ternary leaves a gap in
  the other branch.** `DibbsAwardIntelligenceRow` rendered an empty slot when
  `priceIsUnknown` was false but the display text was also null, because the
  fallback string only lived in the `true` branch. Fixed by making the display
  text the single fallback for both.
- **A migration that looks necessary may already be unnecessary — check before
  writing one.** Part 2 needed zero migrations because P13's generic-identity
  bridge (`20260820010000_funding_opportunity_generic_source`) already widened
  `client_funding_opportunity_source_chk` to admit `'dibbs'`, specifically so
  future phases wouldn't need to. This is the OPPOSITE of D-63
  (`tango_sync_checkpoint.resource_type`, which really was never widened and
  really did need a workaround). The two situations look identical until you
  read the actual migration file — do that before assuming either way for any
  new source.
- **A source-scanning test will fail on a correct change, and that's the
  point.** `funding-opportunity-identity.spec.ts` regex-matches the literal
  `INBOX_SOURCES = [...]` line as text, not as a runtime value. Widening the
  array correctly still fails this test until the literal in the test is
  updated to match. Don't work around it — update the assertion, and keep the
  comment there noting the SPREAD (`[...OPPORTUNITY_SOURCES, ...]`) is what's
  actually load-bearing, not the specific names after it.
- **Don't use a source that's about to become legal as your "this should be
  illegal" test example.** The inbox spec used `'dibbs'` as its unknown-source
  400 case; part 2 made `'dibbs'` legal, so that test started asserting the
  opposite of what it meant. Moved to `'sbir_sttr'`, which is durably the right
  choice: it's `isStorableSource() === true` (in the database CHECK) but will
  never be `isStorableSource` visible through `OPPORTUNITY_SOURCES` or
  `INBOX_SOURCES` until P42 ships — so it can't accidentally become legal the
  way `'dibbs'` did.
