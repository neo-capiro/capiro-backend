# Portfolio onboarding foundation checkpoint

The active profile-build controllers use the existing durable fill run/task/finding tables for clients and prospects. Explicit empty source selection remains document-only. Run request identity, retry attempt checks, per-finding revision checks, cancellation and late-write fences are retained. The detached legacy source runner was removed; historical runs remain readable.

Client and prospect profile facts record person/research/official/legacy origin with immutable versions, current pointers, original evidence, and explicit conflict decisions. Existing values are backfilled as legacy with unknown provenance. Manual edits use canonical domain owners; geographic edits invalidate resolution through the facility transaction helper. Manual code entry distinguishes active catalog references from format-valid unverified codes; retired codes are rejected. Source evidence is not inferred from a model confidence score.

Source publication requires the selected attachment to be shared with all profile viewers. Saved pending findings and conflicts are omitted when the original source is no longer shared. Published, explicitly approved canonical values remain, while their inaccessible source evidence is redacted. Converted document links retain their original prospect owner and require current source-prospect access. No S3 resource is duplicated or ownership broadened.

Conversion, fact carryover, child-ID remapping, pending review carryover, source-run cancellation, and client successor task creation commit in the canonical conversion transaction. A process crash cannot lose successor work. Existing active client research causes an explicit recoverable conflict. Original source run and finding identities remain in provenance. Capacity and durable conversion receipt replay remain owned by the existing conversion service.

The prospect view exposes Company basics, Federal registration, Leadership, Lobbying history, Federal footprint, and News. Selected public-web or document tasks produce reviewable sourced findings. Federal footprint reuses the filtered, read-only dossier reference rail; it does not mark references as approved profile facts. Research status records completed source checks even when no records were found. Unresolved identity or unavailable source coverage remains explicit.

New client capability proposals are staged within the same fenced research transaction and use the portfolio review owner; their legacy finding is informational so it cannot create a second independent approval. The SDK consumes selected source corpora, and its task audit is written into the existing attempt. No production database queries, provider/model runs, deployments, or remote push were performed for this checkpoint.

Validation recorded in this worktree: 35 manual parser tests and targeted strict parser typecheck; source-visibility, real PGlite migration/fact/conversion, prospect-document extraction, and projection tests. The final targeted run passed 65 tests, including the actual canonical relationship association and durable review receipt replay/rollback; one unrelated meeting pagination test fails identically on the unchanged baseline (`portfolio-a1.safety.spec.ts`, continuation after a preceding row disappears; `undefined.map`). The PGlite cases execute the migration and verify tenant/subject foreign keys, RLS, conflict preservation, conversion rollback, durable successor tasks, and current source restriction. Integrated application typecheck and full affected regressions are coordinated by the integration owner; this document does not claim those gates have passed.

Profile section arrays currently perform add/update operations. Existing-row removal stays with canonical profile section delete routes and their dependency/audit rules; the onboarding editor must not present omission as deletion.

Relationship-history review now composes the canonical association transaction with finding acceptance and audit, preserves source revision checks and actor-owned source visibility, and delays attachment indexing until commit. Physical document deletion removes only resource links, releases the optional fact attachment FK, and leaves approved fact history plus an unavailable original-source pointer. Corroborating research never downgrades person authority; restoring a rejected research fact reopens its person conflict.
