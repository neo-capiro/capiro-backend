# Calendar source facts for a proposed DC-window integration

Status: **SOURCE FACTS ONLY / PROPOSED INTEGRATION USE.** This document does not implement a calendar integration, retrieval job, scorer, recommendation endpoint, plan/wave model or policy. It does not verify deployed routes, current database contents, current source health, calendar completeness or live availability.

Audited repository: `neo-capiro/capiro-backend` at immutable source `cd3c51e940f14e1b2a1040b0ffa445e85d68b332`. The isolated frozen checkout was read only. No backend source or qualification artifact changed; no provider, AWS, paid job or live database was called. No secondary capirov2 source was required for these findings.

Existing contracts can supply **known published legislative-event context** and **Strategy planning reference milestones**. Neither establishes a free DC week, office availability or a ranked travel recommendation.

## Event time, status and provenance

The existing `CalendarEvent` interface and actual hydrate projection expose these facts:

| Concern            | Existing fields                                                                                                        | Meaning and limitation                                                                                                                                                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Identity/scope     | `id`, nullable jurisdiction/session/stateCommitteeId, congress, chamber, committee and subcommittee names/system codes | A published proceeding and its legislative body, not a member's or staffer's office calendar.                                                                                              |
| Schedule           | `date`, nullable `startsAt`, nullable display `time`, `timezone`, nullable `location`, nullable `timePrecision`        | `startsAt` is the authoritative instant when present. Display date/time are not a substitute for an instant.                                                                               |
| Lifecycle          | `eventType`, `eventStatus`, `visibility`                                                                               | Proceeding status is separate from stream/capture status. Federal event statuses are scheduled/postponed/canceled/in_progress/completed; the legislative projection also supports unknown. |
| Observed freshness | `calendarRevision`, `calendarCheckedAt`, `calendarCheckState`, `sourceRevision`, `lastOfficialUpdateAt`                | Preserve supplied values. They do not establish a reviewed freshness threshold or complete chamber/session coverage.                                                                       |
| Source evidence    | `officialPageUrl`, official playback page/kind, agenda and documents; separate update feed source URLs                 | Public event evidence can be cited. A playback/stream state is a media fact, not an available meeting slot.                                                                                |

Sources: [CalendarEvent interface](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/live-hearings/live-hearings.service.ts#L73-L137), [actual response projection](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/live-hearings/live-hearings.service.ts#L1288-L1330), [discovery status/chamber types](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/hearing-discovery/hearing-discovery.types.ts#L17-L38).

The underlying legislative `CalendarTime` is `{ date, rawTime, timezone, precision, startsAt, endsAt }`, with precision `instant | date | relative | unknown`. Validation rejects a non-instant precision carrying an invented start instant; an end must be a valid instant after a valid start. `CalendarEvent.timePrecision` itself is typed as optional string/null, so a consumer must preserve unknown or unrecognized values instead of narrowing them optimistically. [Calendar facts and observation contract](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/hearing-discovery/legislative-calendar.ts#L5-L74), [time validation](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/hearing-discovery/legislative-calendar.ts#L100-L119).

The schema explicitly prohibits parsing the display wall-clock string back into an instant. Date-only events have `startsAt = null`; no fabricated midnight is allowed. The existing timezone derivation preserves explicit official local-zone evidence and handles Eastern date-only sentinel semantics. A field-hearing location alone must not infer its timezone. [Schema timing contract](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/prisma/schema.prisma#L7232-L7240), [timezone authority](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/hearing-discovery/hearing-time.ts#L18-L30), [date-only sentinel/day handling](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/hearing-discovery/hearing-time.ts#L59-L110).

`CommitteeHearing.scheduledEnd` and snapshot `time.endsAt` exist in persistence, but the canonical public `CalendarEvent` projection does **not** expose a scheduled end. `capture.actualEnd` is a separate recording outcome. Do not turn a start-only event into a fixed-duration busy interval. [Stored end and precision](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/prisma/schema.prisma#L7221-L7227), [federal snapshot time shape](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/hearing-discovery/federal-calendar-transition.ts#L58-L73), [public response shape](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/live-hearings/live-hearings.service.ts#L94-L127).

Field-level `calendarProvenance`, source observations, observation revisions and legislative transition history are persisted. Observation provenance records source ID/priority, source publication time and changedAt. These internal records are not automatically part of the public calendar row. Partial/omitted fields preserve prior values; an older dated official observation cannot regress a newer confirmed revision, and polling recency does not compete as source authority. [Projection rules](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/hearing-discovery/legislative-calendar.ts#L159-L200), [persisted projection/observation records](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/hearing-discovery/legislative-calendar.repository.ts#L237-L297), [history models](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/prisma/schema.prisma#L7311-L7338).

In the federal writer, `calendarCheckState` is assigned `complete` or `partial` from `projected.agendaComplete`. It must not be reinterpreted as proof that the whole congressional date range, every event field or all office calendars were checked. [Federal writer](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/hearing-discovery/federal-calendar-transition.ts#L76-L108).

## Strategy reference baseline and verifier caveat

There is a separate existing `GET /strategy-api/reference-calendars`, protected by `TenantGuard` and `StrategyPlannerGuard`. It returns `ReferenceCalendars = { congress, ppbeLanes, ppbeCurrentPhases, source }`. Each source-level `ReferenceRow` has `id`, `kind`, `label`, nullable `fy`, nullable `startsOn`/`endsOn` Dates, nullable `tone`, and `position`. The per-kind source is `baseline | override`; tenant rows replace the baseline for a kind when present. The selected public rows do not contain chamber, official source URL, time precision, publication/observation timestamp, freshness or coverage fields. [Route/guards](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api-strategy/src/reference/reference.controller.ts#L9-L17), [Strategy prefix](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api-strategy/src/main.ts#L21-L25), [source types/merge](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api-strategy/src/reference/reference.service.ts#L6-L75), [selected fields](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api-strategy/src/reference/reference.service.ts#L158-L167).

The default baseline is explicitly Capiro-maintained and ported from prototype quarter-position bands, then mapped to dates against the fiscal calendar. Its sixteen congressional bands include broad phases such as Hearings, Member requests, Committee markups and Conference. They are planning references, not a verified official chamber sitting/recess feed. Tenant forks are also user-maintained planning rows. This audit did not read deployed baseline/override contents. [Baseline provenance/bands](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api-strategy/src/reference/baseline.ts#L1-L50), [date materialization](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api-strategy/src/reference/baseline.ts#L86-L104), [fork validation/write owner](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api-strategy/src/reference/reference.service.ts#L79-L105).

Strategy's existing `checkRecess` matches supplied reference labels against `/recess|state work period|district work/i`, requires valid start/end dates, and reports an error only when an action is wholly inside such a row. It returns no violations when the input lacks matching rows; its comment says the baseline lacks recess rows. This is a data-gap-guarded action validator, not session discovery, a recommendation scorer or evidence that a week is in session. [Verifier input contract](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/packages/strategy-verifier/src/types.ts#L44-L68), [recess check](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/packages/strategy-verifier/src/verify.ts#L287-L313).

## Proposed integration boundary; unresolved requirements

The source-backed use is to show or cite known events, their source/status/precision, their observation metadata, source-health context and explicitly labelled Strategy reference phases. Do not interpret absent events, no verifier error, healthy publishers, null starts/ends, capture state, or missing tenant follows as positive availability.

The inspected contracts do not establish complete chamber sitting/recess calendars, week availability, member/staff office free/busy, travel feasibility, person/team capacity, plan/wave membership or a DC-window ranking policy. These remain required inputs/decisions before implementing a recommendation contract. This document proposes no numeric weights, age threshold, default duration, attendance assumption, client priority, eligibility test or schedule-writing authority.
