## Vendor sources and application graph

Before any addon/dispatcher invocation or policy gate, both inventory and runtime modes collect static source evidence for actual physically resolved `@openai/codex-security` and `onnxruntime-node` owners. Manifest/owner/entry resolution does not execute the entry. Bounded JS source files are captured as exact base64 bytes with full-file SHA256/size and explicit prefix completeness. Entry and other files are distinguished; the latter are not automatically designated selectors. Known-source text is useful for review, but the implementation does not invent a platform selector interpretation.

Bounds: at most four owners, 256 visited directories per owner, depth twelve, 2,048 entries in one directory, 128 JS files, 64 KiB per source prefix and 256 KiB captured bytes per owner. Files larger than 8 MiB, symlink sources, source mutation, traversal/entry escapes, missing entry and exhausted budgets remain explicit unproven evidence. No environment files, application credentials or provider APIs are read. Both selected payload and activation remain unobserved until actual vendor logic is reviewed.

The API collector starts from the actual deployed `/app/apps/api/dist/main.js`. It records hash-bound source identities and bounded literal import/require **candidates** with physical resolution, without executing application modules. It is deliberately labeled a lexical inventory, not an AST/control-flow graph: comments and strings may create false positives, and dynamic imports, plugins and configuration may introduce missed edges. Therefore reachability for both vendors is always `UNPROVEN`; lack of a candidate edge is never proof of nonuse. Limits are 64 source nodes, 256 edges, 64 KiB per source and 512 KiB scanned bytes. Incomplete/escaped/unresolved input is retained, not promoted to admission.

Optional fixed read-only provenance locations `/qualification/source-commit.txt` and `/qualification/pnpm-lock.yaml` are inspected only if present. The current image does not promise these mounts; absence is explicitly unverified. A future coordinator must separately review and bind any mounts to its exact frozen source/lock manifest. This proposal does not change Dockerfile or mount configuration. A copied marker/hash or package owner alone cannot prove installed-lock equivalence. The source packet already binds the reviewed probe bytes; no target-only vendor source or frozen-lock observation is fabricated locally.

## Complete evidence plan and boundaries

The collectors run before the corresponding final policy assertions. All provider errors and bounded vendor/API source observations are retained alongside existing child errors and numbered receipts. Existing independent Sharp/LibSQL/Canvas/esbuild/Prisma/import/rootfs/HTTP/TLS/signal checks continue. Collection is one explicit contract for all sixteen symbols and all twelve selectors; this work does not propose one paid probe per missing fact.

After static target facts are available, review exact vendor selector branches and configuration, actual target conditions, physical selected artifact hash and an appropriately complete application dependency graph. Required or optional package relationships describe the owner, not every bundled binary. A payload may be called inactive only with exact vendor selection evidence; a package may be called unused only with sufficient actual reachability evidence. Foreign header identity and incompatible ELF metadata must remain in the inventory even for proven inactive siblings.

ONNX inference remains `UNRUN` without an approved offline fixture. Establish product reachability and selected payload first. A required ONNX parent is not proof of a production inference call, and absence of a fixture is not an application failure. There is no model download or invented inference workload.

Offline fixtures validate real synthetic ELF table relationships, defined versus undefined/versioned symbols, corrupt tables, calculated-versus-observed address labeling, per-provider failure continuation, changed file identities, source bounds, physical source owners, nonexecution and lexical graph uncertainty. Actual Linux ARM64 collection and actual vendor selector/source observations remain **UNRUN** until separate reviewed authorization; local fixtures do not prove target symbol exports, selector behavior or application readiness. Existing child/capture/output caps remain unchanged: exceeding a bound is HOLD, not silent truncation or authorization to raise limits.

The qualification probe was already beyond the repository's file-size review signal. These functions extend its existing evidence responsibilities, with no production module/dependency and no second loader or alternate acceptance path. Independent review must assess parser arithmetic, output bounds, unsupported formats and unchanged fail-closed gates before any commit/publication or future execution.
