## Format provenance and scope

All named artifacts retain their actual first16 bytes as hex, exact SHA256, size and mode before classification. ELF classification still requires its bounded sections and real dynamic dependency strings. PE requires the actual DOS/PE signatures, bounded optional/section headers, known positive optional-header kind and consistent known machine width. Little-endian Mach-O64 requires its actual magic, supported file type and bounded load-command table. Unsupported formats, including unsupported universal/32-bit variants, stay UNKNOWN; filenames and platform directory names never establish a binary format. PE/Mach-O identification is bounded header evidence, not loader or operation acceptance. These foreign objects never enter the Linux native load gate.

The six `.so` files from `quickjs-wasi@2.2.0` are positively identified WebAssembly v1, not ELF. The adjacent `QUICKJS-FORMAT-PROVENANCE.json` preserves the primary receipt: frozen-lock integrity and exact published tarball SHA256 verified, all six target file hashes/sizes equal vendor bytes, actual magic `0061736d01000000`. The probe requires that header plus exact owner/version/relative path/size/hash for the known vendor classification. Its scope remains vendor byte identity and format only; native load is not applicable, provider/runtime operation is UNRUN. Different bytes, owner, version or paths do not inherit this provenance. Portable Wasm is never reported as a native ARM64/musl pass.

The other seven formerly non-ELF addon rows had hashes but no magic in the old terminal receipt. Their actual PE/Mach-O format cannot be established retroactively. The new parser will record positive supported headers if observed; otherwise those rows remain explicit unknown coverage. A source fixture pass does not identify the historical payload's actual format or prove runtime success.

## Package ownership and payload activation

Installed dependency versions are checked against their actual resolved physical package owner. Exact equality remains supported; ranges use the already deployed canonical node-semver7 library, with its contained manifest/entry identity recorded. No library installation or custom semver evaluator is introduced. The terminal inventory includes semver7.8.5. Canonical range evaluation admits `^0.1.18` to installed `0.1.31`; an exact-pin-only failure was a probe coverage defect, not evidence of version mismatch. Missing range engine, invalid ranges and nonmatching versions remain HOLD.

The required/optional relation describes the installed package, not every bundled platform payload. The known Codex Security and ONNX bundled payload roots are recorded distinctly from separately installed platform packages. No basename/platform-directory inference is used to establish format or ABI. Required ONNX package ownership does not prove that each bundled foreign payload is selected. Conversely, a package being optional does not prove a bundled payload is inactive. This proposal reports `BUNDLED_PAYLOAD_SELECTION_UNVERIFIED` with exact payload, physical owner and admitted package relations until real selector/reachability evidence is reviewed. It does not silently exempt those payloads. Existing active-binding and actual musl mapped/loader proof remain mandatory. The ONNX dispatcher still explicitly HOLDs without an approved offline inference fixture; this proposal neither downloads a model nor invents a call.
