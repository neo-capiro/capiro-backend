Target prerequisites: native PostgreSQL 16.15 at root's pinned private endpoint; native gen_random_uuid with an explicit fixture-only legacy default wrapper; owned writable fixture schema; ordinary row-lock/deadlock detection; two or more independent sessions; maintenance visibility of `pg_stat_activity`/`pg_blocking_pids`; no app-role owner membership. A bounded statement/lock timeout caps hangs. Do not require altering global server settings, pg_hba, production grants or network configuration.

Two transactions cannot guarantee which process is the deadlock victim. Record both outcomes and SQLSTATE. If writer rolls back, the reader may legitimately return under the surviving grant; if reader aborts, no result is returned. In either case no partial transaction may be committed accidentally. The test must subsequently demonstrate committed revocation refusal. This is the native availability gate documented in the original source handoff.

The targeted fixture grants Workspace table UPDATE solely because current owner SQL uses FOR SHARE and no original Workspace grant bootstrap exists in these migrations. It leaves the saved-version immutability trigger intact. This is an explicit **test prerequisite**, not a proposed product permission change or evidence of deployed permissions. The source-action table retains SELECT/INSERT only and is read without FOR SHARE. Revision/history tables retain revoked UPDATE/DELETE.

The matrix lists desired owner boundaries, not completed native results. Current runner implements eleven named native groups; only future native receipt statuses qualify implemented subcases. Optimistic Objective write/revision rollback, richer saved-owner collaborator/prospect/source mutation matrix, conflicting different stage request IDs, and rich provider/lease orchestration are not yet covered by these first eleven groups.
