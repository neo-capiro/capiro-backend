# Scoped procurement Money Flow and Hub summary

This follows `sam-action-contract-v2.md`. It does not establish populated source coverage or a live financial result.

The existing continuity producer owns original-source award observations. Its finite enrichment mode supplies validated full-award snapshots to the existing v2 catalog classifier. The existing SAM producer and independent qualification header/member process continue to own actions. Neither producer approves itself. No PIID-keyed enrichment table, scheduler, source pipeline, base-ledger grant or parallel vendor-identity registry is introduced.

`ProcurementMoneyFlowService` owns the authenticated read adapter. `public.defproc_money_flow_scope_v2` owns the one-statement classification, exact-decimal aggregation, attribution and freshness projection. The new function reuses the admitted `classified` and `award_classified` kernels, preserving current revocation, physical membership, source-clock, fork and known-time behavior. Existing public flow/family views and their rights are unchanged.

Core exposes two **read-only POST** endpoints, with its existing tenant middleware and `RolesGuard` (standard_user, user_admin, capiro_admin):

- `/api/defense-budget/procurement/money-flow` returns groups plus their conserved selected totals.
- `/api/hub/procurement/summary` consumes the same service and returns the same scope, totals, coverage, sources and knowledge clock plus group count. This is a procurement summary; it does not relabel Hub's active-opportunity metric as spending.

Both accept `ProcurementScopeRequest`: 1–25 distinct full canonical `awardIdentityKeys`; optional `knownAt` and `sourceThrough` exact UTC microsecond strings. No tenant/client ID or database role is accepted from the body. These are public federal source awards, not client-private rows. There is no implicit parent/descendant expansion. Requests must name every award in their scope. The SQL boundary revalidates complete canonical keys and clock calendar/precision; a future knowledge clock refuses. Missing function/rights/runtime failure yields unavailable, never a legacy fallback or operator connection.

The response contract is `defproc-scoped-money-flow/v1`. Money and bigint counts are strings, computed by PostgreSQL numeric/bigint. Action outlays remain NULL when unknown. The response is always `partial` with measure `qualified_observed_actions` when selected observations exist, never a claim of complete historical/federal spending. No selected actions returns `unavailable`, totals NULL and groups empty. Coverage contains disjoint classifier **counts**, not unqualified/ambiguous financial totals. Omitted coverage categories are unobserved in that snapshot, not evidence of source completeness.

Grouping uses fiscal year (October boundary; undated remains NULL), source awarding agency/subtier, contractor label, validated source UEI, attribute state and vendor key. Only an exact source-reported canonical UEI supports cross-award vendor grouping. Missing/malformed UEI uses the full award key, so identical names never combine unrelated legal entities. UEI is source attribution, not independently verified SAM registration, parent-company consolidation, market-share completeness or event-time ownership. Missing and forked catalog observations remain explicit groups, without invented names/identifiers. No guessed numeric-PIID quarantine is used.

Each group reports latest source revision, observation/recorded clocks and catalog recorded clock. A bounded provenance list binds each scoped award to its actual selected qualification run tuple, selected count, original action source URL and chosen catalog revision/source URL/recorded clock. Documentation URLs are labeled separately and are not record evidence. These clocks expose observation age; they do not assert that the provider or a run is current/complete. Repeated/prior/forked/unqualified actions are handled by the canonical classifier before aggregation. No v1 money, ceilings, award totals, budget authority or FEC funds are mixed in. Group sums and selected totals use the identical selected relation/snapshot. More than500 groups/provenance references or1MiB output refuses without truncation. The application uses the existing Prisma read-only transaction helper with one absolute15-second acquisition/query allocation; native cleanup remains awaited and this is not a hard wall-time cessation promise. Finite inputs do not make the underlying classifier scan row-bounded.
