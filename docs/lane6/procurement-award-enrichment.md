# Finite procurement catalog enrichment

The existing `sync-program-acquisition-continuity` entrypoint now accepts an explicit award-only mode:

```
sync-program-acquisition-continuity --award-ids-file <cohort.json> [--commit]
```

The file is a JSON array of 1–25 distinct, exact canonical `CONT_AWD` full IDs, at most 16 KiB. Numeric and leading-zero PIIDs are valid; all submitting-agency and referenced-IDV dimensions remain part of identity. It cannot be combined with the general producer's cap or continuation cursors. `--help` does not allocate a client. Invalid arguments and files fail before client construction. Exit 0 means read-only validation or completed appends; exit 2 means missing configuration or a refused finite cohort; exit 1 means failure, including an unresolved write acknowledgement.

This is a narrow mode of the existing catalog producer, not a new provider ingestion pipeline. It reads only the requested `federal_award` snapshots and latest admissible canonical `acquisition_record_revision` heads for those full keys. It never fetches SAM/USAspending, copies DEV data, seeds contractors, changes grants, runs migrations, writes relationships/gaps/checkpoints or populates the PIID-keyed legacy enrichment table. Its only optional writes use the existing `AcquisitionContinuityStore.appendRecord`. Both `--commit` and exact `PROGRAM_ACQUISITION_CONTINUITY_ENABLED=true` are required. Other existing continuity behavior remains unchanged.

The complete requested cohort is validated before its first append:

- `source_record_jsonb` must retain the original USAspending object. Missing source snapshots are refused; the transformed legacy `raw_jsonb` is not a fallback.
- The stored full ID, parsed PIID and original `generated_internal_id`/`Award ID` must agree. Identity is never resolved by taking the first PIID match.
- A source-reported UEI must be 12 uppercase alphanumeric characters. Missing/null/empty UEIs remain unresolved. Names are labels, not legal-entity identity. Malformed nonempty UEIs and malformed display attributes refuse the cohort.
- Exact source observation clocks are read as UTC strings before driver conversion. Older source snapshots, same-clock contradictory snapshots, unknown existing clocks and latest catalog forks refuse. These are local catalog-observation comparisons, not a claim of authoritative source revision ordering.
- Existing `appendRecord` uses JavaScript Date for persistence. This mode explicitly refuses source clocks with nonzero sub-millisecond digits instead of silently discarding them. It does not alter that shared store's historical semantics.

The two scoped reads each return at most 26 rows; 26 is an overflow refusal, never truncation. Head ties are retained for fork checks. Both modes use the existing Prisma absolute-deadline transaction helper with a 15-second allocation shared by acquisition and work. Dry-run uses a read-only repeatable-read transaction. Commit uses a read-committed transaction and the standard PostgreSQL `SHARE ROW EXCLUSIVE` table lock on `acquisition_record_revision`, with a 1-second lock timeout, before rereading source snapshots and heads. That lock conflicts with all catalog writers, including older producers that know no custom lock key. The whole cohort appends in that transaction. There is no automatic transaction retry. Actual lock privilege, planner behavior, cessation and transaction settlement still require executor evidence; source bounds are not a live timing result.

Receipts include exact full award keys, source observation clock and canonical source-payload hash, explicit source-reported UEI versus unresolved identity, and acknowledged inserted/existing revision IDs. They contain no provider payload or monetary total. A failed append or transaction acknowledgement stops the run without retry. Staged appends are never described as committed: a transaction failure returns `TRANSACTION_OUTCOME_UNRESOLVED` with null inserted/existing counts and unresolved write outcomes. Neither successful rollback nor zero effects is inferred from a lost acknowledgement. Reconcile the original attempt before any later invocation. This receipt is not an action-population qualification, grant, legal-entity corporate-family mapping, complete source coverage or a financial result.

The existing v2 catalog projection validates these canonical observations and supplies latest-known catalog attributes to selected, independently qualified SAM actions. This mode does not approve any action run or make empty Money Flow available. A source-reported UEI is attribution from the retained award observation; independent SAM registration verification and corporate-family resolution remain separate.

Execution prerequisites remain concrete: actual producer login and effective schema USAGE plus SELECT on `federal_award`, SELECT/INSERT on `acquisition_record_revision` (including its UUID default), and actual permission to acquire that standard table lock; exact target and cohort custody, current original-source snapshots, reviewed current image and operational timeout/cessation evidence. PostgreSQL16 requires ownership or UPDATE/DELETE/TRUNCATE privilege for this lock mode: SELECT+INSERT alone is insufficient. This source adds no grant and does not authorize old-row mutation rights merely to enable locking. If no already authorized suitable producer exists, the executor must return that exact rights gap for a separately reviewed controlled mechanism; never substitute a migration credential. Neither operator catalog inspection nor offline tests proves those rights. Source gaps require a separately bounded original-source refresh, not guessed raw payloads. All live reads, population and migrations remain with the executor assigned through Root.
