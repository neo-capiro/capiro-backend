The existing producer's record type is `outbound_campaign`. Its reserved response metadata fields are optional `newsletterStageId`, an RFC-variant UUID of versions1–5 accepted by the current stage owner, and optional `newsletterRevision`, a positive safe integer snapshot provenance value. An absent/null metadata object or absent stage hint remains an ordinary record. Preserve the generic response owner's established handling of unrelated fields. The reserved-metadata parser projects only these two hints; it does not replace the generic response schema. Reject malformed reserved fields through the response contract rather than silently moving them into another workflow.

A valid stage hint together with `outbound_campaign` is only a routing candidate. Generic create/update requests already accept arbitrary metadata, so this marker is not an authenticated origin stamp or a tenant/client/owner/sender/approval grant. The frontend must resolve the existing record ID through the dedicated newsletter record owner. That owner reloads the actual stage, requires the persisted record type and current primary client to match the stage, checks any present reserved revision against the immutable stage revision, and verifies current record-client access. Absent revision remains legacy compatible. The stage owner verifies tenant, Clerk owner and every source client. Delivery additionally checks current active membership and source-client grants. Retry or actor/tenant/client change requires the same current authority. Metadata revision never replaces the authoritative stage snapshot/revision.

Decoding or routing must not POST open, associate a new record, prepare, test, send, upload, reinvite, generate content or approve an action. Explicit current owner intent semantics continue to govern those operations. Dedicated rich-record GET results retain their existing shape; they are not generic `outreachRecord` results or OutreachV3 session receipts. Effectful review/account-status GET boundaries must remain intercepted in synthetic qualification.

The rich Workspace stage UUID identifies `WsNewsletterStage`. Saved newsletter staging separately identifies an exact `WsDocVersion` snapshot/hash and uses an authorized existing OutreachV3 session, expected state version and durable command receipt. UUID syntax creates no relationship between these resources. Do not infer, copy or convert IDs between their endpoints or automatically migrate either flow.

The public parsers distinguish the direct campaign, document-list, saved-preview/check, stage-creation receipt, dedicated stage-read and dedicated record envelopes. They return a bounded JSON copy or a typed shape/identity error. Expected resource bindings compare IDs and revisions; actor, tenant, grants and resource-family authority still come from the canonical owner. HTML remains untrusted text for the consumer's sanitation boundary. Historical test receipts can refer to a prepared version that is no longer returned among current artifact versions; their UUIDs and current sender binding remain checked, and they confer no current approval.

Before enabling each explicit frontend operation, retain ordinary records and legacy producer hints while refusing malformed markers and forged/stale/wrong-type/cross-owner/cross-tenant/cross-client/revoked hints through canonical intercepted owners. The existing public newsletter and renderer exports confer no authority.
