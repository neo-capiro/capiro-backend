# A2 ML-13: preserve mailbox reconnect holds

Base: `ca4de503fb6ec09caf0daf8b976a0f649c6b9665` (`backend-import`). This is the first bounded A2 Core increment, not full A2 or mail acceptance. No schema, migration, manifest, lockfile, shared registry, runtime, proxy or frontend changes.

## Behavior and ownership

Google invalid-grant and Microsoft interactive-consent failures already marked the connection for reconnect, but their top-level sync catches replaced that hold with `error` and a retry hint. The token owners now throw a typed reconnect error only after their existing token-fingerprint/current-member fence durably records `needs_configuration`. Both sync owners preserve that recorded outcome. Missing refresh material, Microsoft missing identity and returned identity/scope mismatch follow the same hold policy.

The small domain-owned `mail-sync-failure.ts` centralizes status, safe diagnosis and retry timing. Resource 401/403 failures surface with a safe access notice and keep the existing 15-minute retry. They can reflect an expired access token or a request predating reconnect, so they do not establish an unrecoverable credential/consent failure. The inherited Exchange-mailbox-absence hold is retained. Generic failure writes condition on the current row still being `connected` or `error`; a concurrent hold, disable or deletion is preserved. Requested scopes, transport mutation replay behavior, existing OAuth ownership and the scheduler's connected/error admission are unchanged. Raw provider diagnostics are omitted from the persisted failure notice.

The existing provider service files are large inherited owners. This change reduces duplicated failure transition code and adds no new domain responsibilities, dependency cycles or external effects. The new helper is 36 lines and the test groups cover only this transition boundary. Independent review must assess these existing-owner edits; file-size limits are not waived.
