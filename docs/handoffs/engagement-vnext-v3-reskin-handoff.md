## Architecture pattern established (apply consistently to any remaining work)

Three tiers, chosen per gap:

- **New vnext-only component** (e.g. `VNextMeetingsWorkspace.tsx`, `VNextMeetingLibrary.tsx`) — when the canonical layout needs real structural changes (row shape, grid vs. flexbox, toolbar arrangement) that would visibly change app.capiro.ai if done in the shared file. Reuses the canonical **data hooks/types only**, never the canonical JSX.
- **Track A — scoped CSS custom-property override, zero shared-file edits** — for pure color/font/spacing on a shared, complex, heavily-tested component (the meeting drawer; Outreach's Steps 1-4 body components). Works because these components already read their palette from CSS custom properties (`--accent`, `--ov3-accent`, etc.) scoped to a class like `.ov3-root` — redefining those same variables inside `.capiro-vnext-root .engagement-vnext { ... }` (a wrapper only ever present on os.capiro.ai) re-themes them with **zero risk** to app.capiro.ai, since that wrapper class never exists there.
- **Track B — small, additive edits directly to shared canonical files** — for genuine structural completions that are real product improvements, not navy-specific (e.g. adding a missing stage pill, making a checklist interactive, building a real "restricted" panel). These **do land on app.capiro.ai too** — sanctioned deliberately, following the precedent Phase 0 set with a real bug fix. Every Track B change is called out explicitly per-commit below.
