## Primary evidence for the four added records

**CVE-2026-13595.** This is a libblkid nested-partition probing use-after-free. The [Debian record](https://security-tracker.debian.org/tracker/CVE-2026-13595) and [DSA-6442-1](https://security-tracker.debian.org/tracker/DSA-6442-1) identify the Trixie fixed package `2.41.5-0+deb13u1`, while Bookworm remains affected. Upstream repairs are [132d9c8a](https://github.com/util-linux/util-linux/commit/132d9c8aa15a8efd0a23d8ca7ed8b98f365e84fa) for the `2.41.5` line and [60ca8616](https://github.com/util-linux/util-linux/commit/60ca8616ac1a223bfb5a713047a37136dd9481ef) for `2.42.2`. A plan requiring absence of every util-linux-origin package could address this package family only after actual final-image inventory proves that absence; no such candidate evidence exists yet.

**CVE-2026-86805 and CVE-2026-95818.** The [86805 Debian record](https://security-tracker.debian.org/tracker/CVE-2026-86805) describes a privileged dynamic-loader path-resolution race with specific hard-link and `$ORIGIN` prerequisites. The [95818 record](https://security-tracker.debian.org/tracker/CVE-2026-95818) concerns a loader stack buffer overflow for particular `$ORIGIN` paths in `AT_SECURE` programs. Neither supplies an AMD64 exemption. Both identify upstream fix [ed0c137b97eb940b4b64981e84ed806d3276edd9](https://sourceware.org/git/?p=glibc.git;a=commit;h=ed0c137b97eb940b4b64981e84ed806d3276edd9). That commit association is verified through the primary Debian records; direct GNU Git access was unavailable. Its presence in Bookworm/Trixie was not established. No host sysctl, setuid inventory or exploitability check was performed, and mitigation assumptions do not clear the scan gate.

**CVE-2026-97399.** The [Debian record](https://security-tracker.debian.org/tracker/CVE-2026-97399) specifies the POWER8 implementation. Because the exact scanned image is AMD64, the implementation scope supports a non-applicability assessment for native execution, rather than proving an installed package fix. This is explicitly an architecture inference, not a waiver. Indexed text from the [GNU advisory correction](https://sourceware.org/pipermail/libc-alpha/2026-October/181027.html) and [maintainer review](https://sourceware.org/pipermail/libc-alpha/2026-October/181042.html) associates fix `e622f82ea8797704ac8f761f88ed3e429e97fedd` with an annotation of `2.45`; direct page/Git retrieval was unavailable. No released `2.45` package or Bookworm/Trixie fixed floor is claimed. Debian's verified distribution fixed floor remains unstable `2.43-7`.

For all three glibc records, Debian's `no-dsa`/minor-issue treatment for Trixie is a distribution servicing disposition, not a statement that the package is fixed and not a release waiver. Current Bookworm/Trixie fixed versions remain unverified. The exact scanned glibc package label is preserved independently of the architecture analysis.

## Candidate limits and receiving gate

The source-only Alpine alternative changes glibc to musl and requires a patched zlib floor plus util-linux-origin absence. That is a **base-family migration proposal**, not evidence that all 11 findings have disappeared. Glibc absence in the final candidate must be established through its complete installed-package and native-artifact inventory; the existing layer report did not select glibc records, and no additional layer download was made for this correction. Later candidate package additions, compatibility packages or native artifacts must not be inferred from the public OS base alone.

A future separately authorized candidate must pass the retained native/ABI and full isolated startup checks, then obtain a supported `COMPLETE` scan for its exact immutable digest. The scan inventory must exhaust pagination and contain **zero findings at every severity**, including informational or undefined findings if returned. Missing, failed, unsupported or incomplete scan evidence cannot pass. Advisory dispositions, architecture reasoning, lower severities and an empty HIGH/CRITICAL subset do not waive that requirement. This document grants no build, base switch, scan start, suppression or rollout authorization.
