## Finding requiring fixture preparation

`apps/api/src/research-portfolios/research-portfolio-current-authority.spec.ts:39` currently clones a row containing nested `grants[0].updatedAt` with bare `structuredClone(row)`. The actual current-resource source requires `grant.updatedAt instanceof Date` at line 55. This repeats the already reproduced Node/Jest Date-realm problem documented in [FIXTURE-REVIEW.md](FIXTURE-REVIEW.md): the cloned date retains its timestamp but can fail the test realm's constructor check. Thus valid-path or drift tests can stop at malformed-facts 503 before exercising their intended branch.

The minimal correction is fixture-only: rebox each original grant `updatedAt` that is already a local Date with the local `new Date(original.getTime())`, retaining NaN and every original timestamp. Keep non-Dates malformed; do not weaken production validation or assertions. The issue was sent to root before qualification. This is a source prediction supported by the saved realm proof, not a claim that this new specification has been executed. Its disposition is pending in the reviewed snapshot.
