# Profile identity acquisition

The existing `POST /clients/profile-build/identity-preview` now acquires candidates from the canonical read-only resolver, the existing SAM read client, cached LDA client and SEC filing sources, the existing public-search owner, and guarded company About/Contact or state-record pages. Availability is explicit in `sourceGaps`. Name-only matches require the chooser. Exact supplied identifiers, or name plus supplied domain, can produce one confident candidate; conflicting identifiers cannot. No canonical identity or profile is created by preview.

Preview accepts `name`, optional `website`, `state`, `city`, bounded `identifiers`, and one optional `attachmentId`. `name` may be omitted for a supplied website or authorized ready identity upload. The canonical `EngagementService.extractIdentityUploadText` owner supplies provider-free document text, checked before and after extraction. The bounded Portfolio SDK quotes actual company names, then the same public-source acquisition runs for at most four supported names. Filename/default identity guesses are prohibited. The document owner is rechecked after the asynchronous work.

An external candidate carries `entity.id: null`, `sourceCandidate: {source,externalId,name,website?}`, `evidence`, and `claims`. Sources are `sam`, `lda`, `sec`, `website`, or `document`. Claims have `kind` (`alias`, `former_name`, `parent`, `subsidiary`), `name`, `quote`, and exactly one `sourceUrl` or `attachmentId`. The person explicitly chooses both the company and any relationship claims. The browser must retain the selection through the confirmation request, and must not create the profile or start research before confirmation succeeds.

`POST /clients/profile-build/identity-confirm` accepts `{requestId,sourceCandidate,claims?}` and returns `{requestId,canonicalEntityId,sourceCandidate}`. It re-reads the exact official identifier or the current website/document text, checks name and current relationship quotes, and calls the existing canonical registration owner. It does not trust preview payloads as official proof. A normal audit command receipt supports exact retries; source selection and actor are bound to its digest. Existing client/prospect create then consumes `canonicalEntityId`, preserving current duplicate/capacity gates. There is no hidden client, prospect, token authority, or parallel resolution ledger.

Official identifiers use the existing authoritative global registration boundary. Website/document-only identities use its tenant-private owner and reject overlaps that would silently attach a shared domain or same name to another identity. Public-search links are evidence/source records; only same-origin pages of the person's explicitly supplied company URL carry a company website claim. Private excerpts do not enter shared canonical metadata. Public-source person-reviewed aliases use tenant-private links; document aliases and all relationship claims use existing immutable Knowledge events/assertions with exact excerpts and `human_confirmed` authority. Public quotes are tenant scoped; private identity-document quotes and aliases use the same user scope as existing private Knowledge evidence. No claimed parent/subsidiary identity is silently merged or invented.

All language-model work uses `PortfolioAgentService` with source-only tools, four turns and a bounded per-extraction budget. The existing public-search preview deliberately never invokes the legacy model reconciliation provider or appends resolver history. HTTP disconnects abort stateless previews and SDK work using the same event policy as Meri. No live model, registry, source website or production data calls were used in validation.

Deterministic tests cover read-only acquisition, scoring/conflicting identifiers, domain collisions, exact re-read and receipt replay, actor revocation, source outage, actual document-text derivation, empty/denied uploads, source/name/quote validation, private evidence scope and HTTP cancellation. Root integration supplies module wiring and the canonical upload reader/link endpoint; full build and native browser gates remain centralized.
