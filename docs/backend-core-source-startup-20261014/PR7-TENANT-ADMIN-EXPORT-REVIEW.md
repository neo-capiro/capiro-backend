# Independent review: Core startup TenantAdminService export

Baseline published PR7 `9b9f98d86aebe79721b3655e5a619b27be9a43e9`, tree `8e715d78793b5e2642f67cd7bfa8c0f3c373b336`, registered `TenantAdminService` in `TenantAdminModule.providers` without exporting it. `WorkspaceCollabModule` imported that module and registered `NewsletterAccountProvider`, whose second constructor dependency is the exact `TenantAdminService` class token. Importing both modules into `AppModule` does not make a non-exported provider visible across that Nest boundary. Attempt 3 loaded 1,610 published Git source blobs and failed at Nest construction with that exact dependency error; no module inventory, route initialization or full startup completed.

The root's subsequent commit `04554d8fd861487f3616088dee7943b48ef5c988`, tree `52a2d23d622f7fdc796ea63e27280c97e8579911`, adds only `exports: [TenantAdminService]` to `TenantAdminModule`. This is the minimal owner-wiring correction. It leaves the service, controller, WorkspaceCollab provider, newsletter authorization SQL, Clerk behavior, role decorators, DTOs and app imports unchanged. The existing newsletter provider calls `team.updateMemberRole(ctx, userId, 'user_admin')`; its upstream newsletter authority path derives the saved author and tenant from bound database rows and checks live membership, client walls and required admin state. The exported service's method still performs its existing self/target membership checks. This review does not qualify those behaviors natively or claim that the export alone proves startup.

Attempt 3 also emitted a **separate** late unhandled failure: the AWS shared-config loader tried a credential-file `readFile`, which the harness denied before reading. The JSON report was already written when stderr captured that failure. Preserve both raw streams and classify the run as held. A later harness needs to capture/settle pending asynchronous constructor/config work before finalizing a report, retain fail-closed sensitive-file denial, and prove no actual credential read, network call or worker activity. Do not turn the denial into a silent success. This note involved source and raw-output reads only; no unpublished Engagement `e01…` body, tests, database, network or product edits.
