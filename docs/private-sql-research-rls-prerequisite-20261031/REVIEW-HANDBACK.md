## Forward behavior and baseline

`research-tenant-policies-forward.sql` runs in one transaction. It locks only the three named tables, with a three-second lock timeout and ten-second statement/idle limits. It requires ordinary persistent, nonpartitioned tables with no inheritance, both RLS flags initially false, zero existing policies, and a nonnullable UUID `tenant_id`. It rejects superuser/BYPASSRLS table owners and ownership by either private SQL role. These are proposed fail-closed preconditions; no target owner or current catalog was observed. Existing owners, grants, policies on other tables, data, schema columns and role memberships are not changed. An unauthorized operator fails PostgreSQL ownership checks; the proposal grants no operator rights.

Both shared helpers must be the existing zero-argument stable, invoker PL/pgSQL functions with their canonical return types and exact source-body fingerprints from `20260501000000_init_identity_tenancy`. Only CRLF-to-LF is normalized for comparison. No helper is created or changed. Any function-body/configuration drift requires separate disposition rather than silent replacement. Parent controls concurrent schema work; no shared helper DDL is authorized by this transaction.

Each new policy has the existing canonical expression in both `USING` and `WITH CHECK`:

```sql
public.rls_bypass() OR tenant_id = public.current_tenant_id()
```

`AS PERMISSIVE FOR ALL TO PUBLIC` makes the existing canonical default policy applicability explicit. It grants no table access. Missing, empty or invalid canonical tenant context gives no tenant match; matching `app.current_tenant` admits the tenant; the existing trusted `app.bypass_rls='on'` path remains supported. `FORCE` subjects an ordinary table owner to the policy. Superuser/BYPASSRLS runtime sessions remain PostgreSQL bypasses; this source does not claim to eliminate existing privileged access. Current membership, portfolio grants, archived-state behavior and source-specific visibility remain in their existing application/view owners. No actor/client selector is reinterpreted by these policies.

Replay, partial RLS state, any existing policy, owner/type drift or helper drift refuses before the first policy mutation. There is no DROP/REPLACE, disable-RLS step, broad grant or owner substitution. An error aborts the transaction; parent must rollback/close that failed transaction and preserve its evidence.
