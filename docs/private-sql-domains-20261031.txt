1. Client meetings — implemented Core composition, DB/wire dependencies outstanding
Identity: logical client_meetings -> fixed meri_private.client_meetings, never public.meetings. One row per(client_id,id) association. One saved meeting may match two visible clients; COUNT(*) counts associations and COUNT(DISTINCT id) counts saved meeting rows. Cross-mailbox iCalUId deduplication is dormant in the current domain and is not invented here.
Exact fields/types/nullability are in engagement/meeting-query-projection.ts: client_id/id UUID-text nonnull; subject string nonnull; starts_at/ends_at timestamp nonnull; time_zone nullable string; status/source nonnull strings; is_internal/is_virtual nonnull boolean; provider nullable string; created_at/updated_at nonnull timestamp.13fields, freshness updated_at, no assertion of upstream sync completeness. Join ONLY client_id -> client_profiles.client_id. This corrects the prior proposal's mistaken client_profiles.id reference.
Current authorization: reuse the semantics of engagement-access.helpers.ts ownMeetingWhere and clientAssociatedMeetingWhere, meeting-resource-authority.ts currentMeetingActor/visibleMeetingClientWhere and engagement.service.ts clientProfileEmails/clientMeetingAssociationWhere. Current member and same tenant; actor-created OR same-tenant actor-owned engagement_connections import; status<>deleted. Explicit client assignment or noninternal/client-less association with manual signal absent/null/Booleanfalse and matching organizer/attendee email. Client inputs are trim/lowercase unique primary-contact and client_people emails; match current citext semantics, no fuzzy matching or meeting-side trim. EXISTS for connection/attendee matches avoids duplicates. Disabled connection status is not an additional exclusion in ownMeetingWhere; do not invent one.
Scope: General sees actor-owned associations with current visible clients; selected client sees only its associations. Internal or unassigned personal meetings without a visible-client association are outside this relation, explicitly disclosed. An explicitly assigned internal meeting remains eligible. Shared visibility alone does not override ownership. Revoked/inactive member or client wall denies current access. Deleted source rows disappear; canceled/other statuses remain queryable; no artificial date/retention window is added. A missing view/role boundary returns SOURCE_UNAVAILABLE, not empty success.
Not projected: join URLs, credentials, raw/association JSON, organizer/attendee identities, transcript keys, notes, preps/debriefs, recording bodies. Their existing readers retain source-specific permissions.

Security barrier/FORCE RLS/current tenant and strict reader/owner checks remain. Common source now expects this exact expanded set and fails closed without it. 3. Classic Outreach — grounded source visibility, application authorization dependency unresolved
Identity: OutreachRecord/public.outreach_records is separate from EngagementCampaign and the two existing client_outreach_campaigns/client_campaign_recipients relations. A future logical classic_outreach_records must use the canonical record UUID, not a campaign ID, send intent or compatibility outreach_v3 root. Candidate saved scalar fields: id,client_id(nullable),type,status,title,subject(nullable),body(nullable full saved text),recipient_count(integer savedcount, not deliverycount),sent_at(nullable),opened_in_email_at(nullable),created_at,updated_at. Do not project raw recipients/stats/metadata or grant send permission. No meeting join is declared merely because a record has a meeting_id.
Canonical current predicates and ordering:
- ownOutreachRecordWhere enforces actor creator and NOT typeoutreach_v3; same tenant and deleted_at IS NULL for ordinary reads. Existing14 campaign permissions are different and stay unchanged.
- engagement.service.ts getOutreachRecord first loads association-only data, checks every nonnull parent/linkedmeeting/latestprep/latestdebrief client, calls assertSavedMeetingPrepAccess, loads the row, compares the association identity, then repeats client/source checks. readOutreachRecordPage similarly filters candidates and hides the whole card if child/source access is lost. Do not bypass this for counts or supposedly harmless title/status metadata.
- Latest prep/debrief is chosen by created_at DESC with take1. There is currently no explicit secondary order for equal timestamps. SQL must not invent an id tie-breaker that selects a more permissive child. Domain owner must define one common deterministic order, or conservatively authorize all tied latest candidates in a shared owner change before SQL depends on it.
- assertSavedMeetingPrepAccess reuses current native meeting/mail/task/note/debrief/client/connector rules and Research artifact/conversation reciprocal bindings. It can require FOR SHARE/FOR UPDATE locks and cannot simply run inside the dedicated READ ONLY query transaction. Missing/invalid source provenance, revoked source/client/grant or changed association hides/refuses the record. Non-authorization infrastructure errors propagate as unavailable, never an authorized empty set.
Required implementation boundary: authorization must precede SQL aggregation. Postfiltering COUNT/grouped results or granting a table view on creator/client alone is invalid. Reuse/extract the EXISTING canonical association/source guard once in the domain owner, retaining current readers as callers. The common SQL owner can accept only a bounded current server-owned set of eligible record identities with currentness rechecked around the query; never copy record bodies into a staging database or introduce another query engine. This is an authorization observation, not a persisted grant/ledger, and it must never treat a truncated candidate scan as the full authorized universe. If the existing deadline/budget cannot observe the full required candidate set, refuse the query and request a narrower scope rather than returning a false aggregate. DB owner must agree how the exact read-only view consumes that server-bound authorization without raw-reader grants. No such context/selection transport is implemented or authorized as complete by this document.
Scope decision to ground with current owner: selectedclient restricts to that explicitly associated visible client. Current General/client_records semantics cover client-associated records, while Classic also has actor-owned client-less records. Do not silently add client-less Classic to the old client_records contract. A future explicitly personal/Classic source may include them under the genuine General/private-user capture with the SAME linked-source rules; Research preparations do not turn General into a Research portfolio scope. This is a distinct source/normalization boundary, not an actor/model claim.
Retention: deleted_at excludes ordinary records; do not introduce trash/history access. Hard-deleted or source-inaccessible records cannot be retained through a stale authorization set. Missing latest parent/child or changed link fails currentness. A sent_at value is historical saved state and never permission to resend or proof of provider delivery.
Needed named source writer: Root to allocate existing engagement/Classic owner for the shared association/source guard and stable latest-child ordering, with Research owner covering institutional prep dependency. Common owner will integrate only the agreed private registry/context; DB owner alone writes its view/grants. No existing Classic handler or meeting-prep authority has been edited here.
Required tests: actor/cross-tenant/nonowner/internaloutreach_v3; deleted/nullclient/selectedclient; wall loss for parent/meeting/latestprep/latestdebrief; no-meeting record; ordinary source grants and confidential notes; disconnected personal connector; Research artifact grant/hash/rebinding/reassignment; tiedlatestchildren; source revocation between preflight/query/postcheck; empty authorized set vs incomplete scan; aggregates leak no denied row/count; no provider/send effect.
