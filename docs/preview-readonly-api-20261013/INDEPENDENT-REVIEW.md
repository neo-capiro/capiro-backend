# Independent preview read review

Reviewed the bounded preview source in `codex/preview-readonly-api-20261013`, based on `c76f5fc0df6688743afeec274211afd2e67fe8f1`. This is a source review of the uncommitted preview worktree, not a deployed or native-database qualification.

The separate bootstrap registers only `GET /api/me`, `GET /api/clients`, and `GET /api/clients/:id`. Its route policy rejects other methods and paths, including implicit HEAD and method-override inputs. It does not register the production AppModule, tenant provisioning middleware, mutations, workers, webhooks, or provider routes. `UsersController` is a provider for the existing `me` method only; its mutation routes are not registered. The client read extraction retains the production tenant predicates, archive default and opt-in, `createdAt` ordering, not-found behavior, and asynchronous logo projection. Preview returns `logoUrl: null` without calling the logo signer.

Before a business read, the interceptor verifies the signed token, the configured internal organization and tenant, an active non-actor Clerk session, and a matching active local user, tenant, and membership. It compares Clerk role claims through the existing canonical role mapper, preserving `admin`/`org:admin` equivalence and the existing internal admin/member mapping. It neither adopts users by email nor creates memberships. A second online session check and local membership read occur after the handler; a changed membership revision or failed authority check refuses the buffered response. The tenant-scoped read queries use the same transaction through AsyncLocalStorage; attempts to open system, user-scoped, nested, or cross-tenant transactions from that context are refused.

The preview transaction starts with `SET TRANSACTION READ ONLY`, checks the connected role and default read-only setting, and refuses table, column, and sequence write grants or ownership before clearing `app.bypass_rls` and setting the tenant GUC. A separate empty transaction performs that role check before the preview listener starts. The source has no normal-production activation path for this preview context. Unexpected interceptor errors become a generic 503 response, so database or credential-bearing exception text is not returned to a caller. The final cleanup removes only the now-unused private bulk logo helper; the production per-client signer and its `Promise.all` projection remain in use. I found no remaining source-level blocker within this three-route scope.

The final `ReadCommitted` membership read is the local authorization linearization point. A revocation after that read, or a delay between a Clerk organization membership change and its local mirror, is not atomically excluded across Clerk and PostgreSQL. The second Clerk lookup runs within a five-second transaction; provider latency can refuse an otherwise authorized read. The database role and read-only behavior still require separate native qualification with the actual preview credentials and grants. No deploy, grants, role creation, native database execution, or live-provider check is accepted by this review. Synthetic/type/build receipts remain owned by the parent and should be attached to the final frozen source separately.
