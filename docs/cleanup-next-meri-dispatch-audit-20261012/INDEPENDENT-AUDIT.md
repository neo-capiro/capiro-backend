# Independent local Meri dispatch audit

The frozen source has a finite local dispatcher suitable for a narrowly scoped extraction, subject to the gates below. This is a read-only design audit, not acceptance of an implemented extraction or of native database behavior. No production module was imported or executed, no tool owner was invoked, and no test suite was run by this reviewer.

Audited PR2412 source: `6a4b48e6286a270ab18c033eb4ccaf6f72f42c70`, tree `f14d6fa3f191645839414972063e1057fce557bf`. Exact frozen/working byte equality and SHA256/blob evidence are in [independent-source-inventory.json](evidence/independent-source-inventory.json); static checks and retained read limitations are in [independent-read-only-receipt.txt](evidence/independent-read-only-receipt.txt). Parent-owned characterization receipts remain separate evidence, not reviewer-executed tests.

## Concrete findings

1. **Existing catch-all registration coverage misses the real switch.** `apps/api/src/meri/meri-tools.registration.spec.ts:677–791` calls the real public `execute` on a Proxy whose generic function trap at lines770–775 also replaces `executeScoped`. Public `execute` at `meri-tools.service.ts:2574` invokes that replacement. The loop can record one call named `executeScoped` for every advertised schema without testing any case target or arguments. Keep this evidence; a passing registration loop alone cannot qualify an extraction. The future harness must preserve the actual dispatch method and stub only leaf ports, or independently evaluate the frozen dispatch body with explicitly inert dependencies and compare it with the candidate.

2. **A constructor-built bound-handler cache changes supported source behavior.** Existing registration and parity fixtures use `Object.create(MeriToolsService.prototype)` and assign fake leaf owners afterward. The governed proxy binds methods to the raw instance (`governed-meri-tools.proxy.ts:200–201`). The current switch looks up `this` methods and optional owners at invocation time. A field initialized only by the constructor breaks those fixtures; cached bound methods also conceal later replacement/availability changes. A local table may contain stateless callbacks, but it must resolve the current instance's ports lazily on every call. It must not cache authorization, flags, user/client scope, or owner availability.

3. **Plain object registry lookup can expand the callable surface.** The switch accepts only134 literal local names and defaults to `assertNever(name)`, yielding `Error('Unhandled Meri tool: ...')` (`meri-tools.service.ts:2896–2897,10482–10483`). A replacement using `handlers[name]` without an own-key check could call `constructor`, `toString`, `__proto__`, or another inherited property. Require a `Map` or an explicit own-key check, with the original unknown behavior. Keep compile-time exhaustion and runtime unknown checks. This is a prospective extraction hazard, not a discovered bypass in the current switch.

4. **Three entry boundaries have different observable error timing.** Raw `executeFromAuthenticatedUser` is synchronous until it returns public `execute`: request-active guard, trim-only name normalization, and write-input parsing can throw synchronously (`meri-tools.service.ts:2466–2478`). Both raw `execute` and `executeScoped` are async, so their guard/default/handler throws become rejected promises. The governed proxy additionally awaits chart admission and wraps both entrypoints through async `present` (`governed-meri-tools.proxy.ts:107–148,175–197`), so raw authenticated synchronous errors become governed rejections. Do not make the raw authenticated entry async, remove an existing async wrapper, or add an await before a leaf invocation. Preserve exact success/error identity except the two existing governed-memory signal translations.

5. **Research Portfolio dispatch is a lazy current-use wrapper, not a direct owner alias.** All19 local RP labels call `executeMeriResearchPortfolioToolAtCurrentUse` and supply `execute: () => this.requireResearchPortfolioTools().execute(ctx,name,input)` (`meri-tools.service.ts:2585–2611`). Delegated transport checks current tenant/user/conversation, current selected client and scope, then re-reads conversation metadata/client across the authorization await before invoking that callback (`meri-rp-tool-transport.ts:124–184`). The genuine legacy/action-proposal path without delegated turn scope intentionally uses separate owner authority. Eagerly resolving the owner, capturing it during table creation, or invoking it before the wrapper changes ordering and can bypass this gate. Preserve the callback, original family name, exact input/context references, and per-use flag/dependency check at `meri-tools.service.ts:457–462`.

6. **Several cases are adapters with observable shaping.** The funding comment at `meri-tools.service.ts:2817` says “verbatim,” but lines2821–2878 shape strings, optional paging fields, and comparison-array entries. `toolActor` at lines247–253 creates a narrow new actor containing only tenantId/userId/role. Do not spread the full tenant context or forward raw funding input. District optional-owner fallback at lines2705–2718 applies `??` to the immediate return value, including a Promise; awaiting then coalescing changes null/undefined Promise results. Word format validation and defaults at lines2771–2775 must happen before its handler. Only `send_email`, `create_word`, and `schedule_task` consume `execution?.actionProposalId`; Excel and PowerPoint currently pass three arguments to `createDocument`, not a fourth undefined/id. `get_pe_budget_timeline` passes `(input,ctx)`; `list_scheduled_tasks` passes only ctx. Exact argument counts, order and reference identity are gates.

## Existing provider-free test evidence and limits

Source-reviewed only: `meri-tools.registration.spec.ts` and `meri-tool-manifest.parity.spec.ts` stub domain constructors and use prototype/fake ports; targeted attachment/funding/RP dispatch assertions are useful, but the generic registration trap has the gap above. `governed-meri-tools.proxy.spec.ts` uses fake raw/federal owners and checks signal/error/success identity. `governed-meri-tools.chart-scope.spec.ts` uses fake raw/Prisma ports for chart scope/bounds/missing dependency. `meri-tool-request-control.spec.ts:17–47` uses fake EventEmitters for disconnect/deadline/ALS cleanup. Outcome reconciliation, schedule controls and create-client specs contain fake stores/ports and protect canonical side-effect/outcome behavior. Their import graphs must remain stubbed when later run; this audit did not execute them or qualify native PostgreSQL/RLS, provider integrations or production cancellation races.

The parent retained an inert293-check frozen-source characterization and its initial `Unqualified direct arg name` harness failure. That is useful baseline characterization, not candidate differential acceptance. The inherited catalog assertion expects138 while canonical catalogs contain139; prior raw failure/source proofs at `docs/cleanup-source-gates-20261012/evidence/meri-catalog-baseline-classification.json` remain unchanged. These failures must not be hidden by broadening exclusions or rewriting assertions.

## Finite implementation-path proposal

After ownership coordination and separate authorization to implement: change only `apps/api/src/meri/meri-tools.service.ts`, add `apps/api/src/meri/meri-local-dispatch.ts`, and add one focused provider-free equivalence spec. Keep both existing async execute wrappers and synchronous authenticated guard/parser boundary; replace only the switch body with a local, stateless, typed dispatch helper called after the same first guard. Resolve leaf ports at use time with their original receiver, preserving every adapter and lazy callback. No new Nest provider/service/store/schema/migration; no constructor cache; no consumer/proxy/module/shared-registry/catalog/request-control changes; no retirement or handler edits. A new helper should not import the production service or provider graph at runtime.

This packet approves only that bounded proposal as reviewable. Implementation and candidate equivalence are pending. Parent retirement ownership coordination remains pending; no retirement paths are inferred here. Separate Engagement reporting work and its branches remain outside scope.
