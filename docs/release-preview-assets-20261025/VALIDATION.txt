Supporting's exact b20d48c review found that ordinary reviewed deletion also requires
missing-object recovery; the initial synthetic-only description was incorrect.
HEAD has no Prefix parameter, so prefix-conditioned ListBucket is not assumed to
convert403 into404. The paired helper must use an authorized, coherent LIST with
Prefix equal to the retained full key and MaxKeys1, distinguish exact from suffix
keys, and preserve ETag/IfMatch/receipts/uncertainty. Never treat403 alone, a present
key, denied LIST, timeout or malformed response as successful deletion. This is
documented-contract reasoning, not live S3 proof. General-purpose bucket lexical
ordering supports the exact-key observation; no directory bucket is used here.
