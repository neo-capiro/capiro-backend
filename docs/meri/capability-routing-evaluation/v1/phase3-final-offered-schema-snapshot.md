# Phase 3 final offered schema snapshot (dark seam)

Status: pure, unused compiler. `capability_routing` remains registered as inactive. This package makes no JEV call and changes neither the schemas offered to the model nor tool execution.

`MeriV3AssistantService.runTurn()` computes `availableSchemas` after `/api/clio/tool-schemas` fetch, surface/callable filtering, `toolPolicy`, and the research lease check. The managed MCP subclass adds connected-app schemas and removes unavailable analysis before that point. A future caller must compile this snapshot from that exact final array, in the same turn, before planning. The compiler intersects only canonical full-chat capability names; noncanonical MCP names affect the schema fingerprint but cannot become routing choices. It binds tenant, actor, conversation, client, and chat/research surface to a versioned, immutable candidate set. The validator rebuilds against the current final array and rejects stale versions, changed scope or schemas, duplicate selections, and choices outside the offered canonical set.

The authenticated V3 controller verifies the API's signed governed context against the bearer-derived tenant/user and the exact DTO conversation/client/messages before entering the assistant. The assistant has no verified-context marker. A direct service caller could pass `ctx` and `dto` without that proof. Therefore this pure compiler does **not** claim its input scope is authenticated by itself, and it is deliberately not called in production. Future wiring must pass a typed proof from the verified controller path or perform equivalent verification at the call site; a DTO field named `authenticatedScope` is not proof.

The API's native `/api/clio/tool-schemas` builder is tenant/surface scoped and does not fully evaluate user/client permission. Consequently a tool offered by that endpoint can still be denied during invocation. The snapshot explicitly marks native user/client permission unresolved; its candidate IDs mean *offered canonical IDs*, not authorized executable IDs. The structural selection validator also returns an `eligibility: unresolved` object rather than a bare ID list, so it cannot be mistaken for an authorized JEV candidate set. Before Phase 3 activation, either produce a user/client-authorized final schema or intersect a server-owned permission decision from the same authenticated turn. The executor's resource-specific checks remain mandatory even then. Do not feed this snapshot to JEV as an eligible choice list while the unresolved marker remains.

No runtime gate was changed. Off-mode performs zero snapshot compilation or new schema enumeration. The existing 14/14 authenticated-scope tests and API typecheck apply to the prior package, not to this one. This package's focused tests cover the pure compiler; production authenticated parity, native permission denial, actual off-path call counts, and end-to-end turn concurrency still require a later integration package.
