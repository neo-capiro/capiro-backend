## Decoder limits

The implementation follows only the observed path `nodes[*].data[0].fedRAMPData -> meta/data -> Products -> product core-field string references`. It uses `JSON.parse`, bounds payload size to 8 MiB, route nodes to 8, graph slots to 100,000, and products to 2,000. It resolves a core scalar through one checked numeric graph index only; product-field targets must be nonempty strings. It does not recursively unflatten objects, interpret devalue tags in product core fields, resolve `ProductsMap`, use `eval`, or infer fields from HTML aliases. Metadata `last_change` is the sole explicitly handled tag (`["Date", ISO-string]`), returned as a string.

It rejects malformed/multiple roots, changed required object shapes, out-of-range references, object/tagged/cyclic/non-string core targets, duplicate IDs, missing/empty core values, unknown status/impact strings, invalid metadata dates, and exceeded size/count limits. `sourceCount` is exactly the parsed `Products` reference-array length—not a Marketplace-displayed total. The returned uncertainty markers are part of the typed result: undocumented framework route data, freshness/completeness unverified, snapshot-array count only, and not suitable for negative claims. `ProductsMap` is deliberately not used, so its consistency is untested.

The [official Marketplace guide](https://www.fedramp.gov/marketplace/guide/) documents JSON export of filtered results, not this SvelteKit route-data URL as a durable full-inventory API. SvelteKit's [load-data documentation](https://svelte.dev/docs/kit/load#Output) describes devalue-compatible server data transport, but that is framework behavior rather than a FedRAMP schema/availability contract. The decoder therefore remains dormant; migration requires an official stable contract or an equivalent operational agreement, freshness criteria, current-source parity reconciliation over repeated observations, and reviewed status/impact semantics.
