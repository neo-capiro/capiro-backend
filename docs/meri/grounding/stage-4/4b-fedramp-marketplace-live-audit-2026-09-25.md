# FedRAMP Marketplace parser source audit — 2026-09-25

Read-only `GET` of the official [Marketplace products page](https://fedramp.gov/marketplace/products/) returned HTTP 200 and 5,038,110 UTF-8 bytes. The [official Marketplace changelog](https://www.fedramp.gov/marketplace/changelog/) says the redesigned Marketplace adds JSON export (lines 72–77), but this audit did not identify a stable export URL or documented machine-readable endpoint in the prerendered page. The page still embeds the records in Svelte assignments.

## Assignment inventory

A scan of assignment-shaped `variable.id="…"` fields found 722 product-shaped IDs matching `(?:FR|F)\d{10}(?:A|XL|XM)?`: 643 `FR` IDs and 79 legacy `F` IDs. Endings were 685 with no suffix, 30 `A`, 6 `XL`, and 1 `XM`. The `FR` family had 27 suffixed IDs; the legacy `F` family had 10. The same document contains other ID assignments and nested product references, so the parser only accepts the bounded assignment grammar above and cuts each record at the next product assignment.

A second read-only fetch and direct parser invocation later the same day returned 5,042,680 bytes and exposed another real product assignment: `FR260215856` (`SandboxAQ` / `AQtive Guard`, `Legacy FedRAMP Ready`, `Moderate`). This ID has 9 digits, so the earlier 10-digit-only grammar rejected it as `Unsupported marketplace product ID shape FR260215856`. The follow-up scan found 723 product IDs: `FR` 10-digit unsuffixed=615, `FR` 10-digit `A`=20, `FR` 10-digit `XL`=6, `FR` 10-digit `XM`=1, `FR` 9-digit unsuffixed=1, `F` 10-digit unsuffixed=70, and `F` 10-digit `A`=10. This same-day source change is captured in the parser regression test and the accepted digit width is now 9–10. It does not establish that future lengths are supported. After this grammar repair, a direct invocation over the 5,042,680-byte body failed at `Incomplete marketplace record FR1820435961`, as expected for its indirect `cso`.

All 722 assignments had literal `csp`, `status`, and `impact_level` strings. 720 also had a literal `cso` string. Two records (`FR1820435961`, `F1506096710`) assign `cso` from identifiers (`aa` and `c`) instead of string literals. Resolving those values requires understanding the generated function call and argument mapping; this parser deliberately does not execute JavaScript or infer them. It therefore raises an incomplete-record error on the live payload instead of returning a partial inventory.

The first payload contained these exact status strings and counts: `FedRAMP Certified` (526), `Agency Authorization In Process` (47), `Legacy FedRAMP Ready` (64), `FedRAMP In Process` (13), `Unknown` (1), and `Initial Implementation` (71). The later fetch had `FedRAMP Certified` (527), `Agency Authorization In Process` (47), `Legacy FedRAMP Ready` (64), `FedRAMP In Process` (13), `Unknown` (1), and `Initial Implementation` (71). `FedRAMP Certified (In Remediation)` is listed in the changelog (line 53) but was not present among either set of page assignments; it is accepted as a source-documented status while every other unknown value still fails closed.

## Repair and operating boundary

The parser now recognizes both observed ID families, observed suffixes, and the observed 9-digit ID, escapes Svelte variable names before building regular expressions (including `$`), and bounds records using the next product assignment. Synthetic regression cases cover `FR…A`, `FR…XL`, legacy `F…`, `FR260215856`, the changelog status, and unknown IDs/statuses. Required fields remain literal-only and mandatory. Because the official live payload includes two indirect `cso` fields, the direct live parse still fails closed; callers do not receive incomplete results. Keep status-provenance enforcement dark until the source supplies a reliably parseable complete record set or a stable JSON export contract is confirmed.

A follow-on status-claim regression found that a trailing word-boundary assertion did not recognize the full parenthesized `FedRAMP Certified (In Remediation)` phrase, even though the new vocabulary accepted it. The detector now uses a non-word continuation check after its length-sorted alternatives, so the exact phrase is classified as one status rather than the shorter `FedRAMP Certified` prefix. The focused status-provenance suite passed 11/11 and the core package build passed. This does not change the live parser gate above.

This is a point-in-time audit, not a claim that the source ID grammar or status vocabulary is permanent.
