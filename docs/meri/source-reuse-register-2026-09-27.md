# Meri V3 source reuse register

**Status:** proposed, unimplemented handoff. This register restores the concrete source map missing from the [native V3 quality plan](native-v3-quality-plan-2026-09-27.md). The [75-case contract](../../evals/meri/live-75-case-spec.md) and [evaluation handoff](../../evals/meri/live-75-agent-handoff.md) supply the acceptance baseline. These files were prepared against Capiro main `d86b0662d1c6c6eb559ce2a74ea3e7244233672b`; recheck the head, deployment digest, effective flags, code ownership, and actual served path before changes.

**What “copy” means here:** retrieve the named upstream file at the pinned commit, study the tested behavior, and adapt the smallest useful part to the existing Capiro TypeScript services and authorization model. Preserve license notices when copying substantial code. A reference link is not a claim that upstream code is deployed, that it is compatible with Meri, or that an experiment passed. Do not restore the reverted Hermes runtime or install its full tool catalog.

## Commitments & Deliverables: preserve the named Meri skill

The existing **Commitments & Deliverables** Quick Action must remain available under that name and ID `commitments_audit`. Its [catalog entry](https://github.com/neo-capiro/capirov2/blob/d86b0662d1c6c6eb559ce2a74ea3e7244233672b/packages/shared/src/meri-skills.ts) is `quickAction: true`, `readOnly: true`, `requiresClient: true`, and names the `query_client_changes` recipe. The [workspace panel](https://github.com/neo-capiro/capirov2/blob/d86b0662d1c6c6eb559ce2a74ea3e7244233672b/apps/web/src/components/chat/MeriQuickActionsPanel.tsx) inserts its editable starter prompt, while the conversation [records skill telemetry and sends ordinary chat](https://github.com/neo-capiro/capirov2/blob/d86b0662d1c6c6eb559ce2a74ea3e7244233672b/apps/web/src/components/chat/MeriWorkspaceConversation.tsx); telemetry is not execution binding. The [current recipe](https://github.com/neo-capiro/capirov2/blob/d86b0662d1c6c6eb559ce2a74ea3e7244233672b/apps/meriv2-orchestrator/src/meri/meriv3/meriv3-retrieval-changes.ts) reads several recent-change services, but its default recent window and lack of an explicit mapped Monday.com read do not establish a complete commitments audit. Capiro has a separately governed [Monday retrieval adapter](https://github.com/neo-capiro/capirov2/blob/d86b0662d1c6c6eb559ce2a74ea3e7244233672b/apps/api/src/retrieval/adapters/monday-managed-mcp.adapter.ts); test that the skill actually reaches it when a selected-client mapping permits it. Preserve the starter, registry, tenant flags, and `readOnly` behavior. A dedicated executable `commitments_audit` firm skill does not currently exist; add a **versioned firm playbook** through the existing firm-skill service instead of implying one already runs.

Adapt these two pinned Hermes MIT procedures as guides:

- [`meeting-action-items/SKILL.md`](https://github.com/NousResearch/hermes-agent/blob/516535b54275e963a82b4c28f866338fb768e7bc/skills/productivity/meeting-action-items/SKILL.md): separate decisions, proposed ideas, explicit commitments, blockers and risks; use transcript/notes provenance; reconcile existing tasks before proposing writes.
- [`document-to-action-items/SKILL.md`](https://github.com/NousResearch/hermes-agent/blob/516535b54275e963a82b4c28f866338fb768e7bc/skills/productivity/document-to-action-items/SKILL.md): carry document version/page, deadline and obligation modality, OCR uncertainty, and cited proposed action. Avoid converting “may” or brainstorming into a confirmed commitment.

Implement through Capiro's selected-client scope, authorized mail/meeting/task/document services and mapped Monday.com where authorized, firm-skill versioning and rollback, and governed Institutional Memory. Each surfaced item needs `sourceId`, `sourceVersion`, `locator`, `observedAt`, `type: decision|commitment|proposal|question|blocker`, `outcome`, `owner|null`, `dueDate|null`, `dependency|null`, `acceptance|null`, `existingRecordId|null`, `proposedAction`, and `status`. Report which source categories were searched, not available, or partial; do not claim complete coverage from one transcript, a seven-day recent-changes read, or a Quick Action prompt. Missing owner or date remains unresolved. Keep the audit skill read-only. A separately requested task update, message, or memory proposal uses the applicable **in-Meri workspace approval**, an operation identity, a read-back receipt, and reconciliation on ambiguous timeout. Summaries do not become approved Institutional Memory automatically.

Keep the canonical 75 cases fixed. Use the separate [Commitments & Deliverables acceptance extension](../../evals/meri/commitments-deliverables-extension.md) for meeting/mail/native task/mapped Monday comparison, partial coverage, an older untracked promise, duplicate reconciliation and a separately approved follow-up in `/meri`. Add a Quick Action catalog/UI assertion for `commitments_audit` visibility and selected-client requirement; the existing panel test covers only five older labels. Never route a normal approval to Settings.

## Implementation record for the remote agent

For each candidate, record: upstream repository and pinned SHA; precise file/function and license notice; current Capiro source/target and effective flag; whether it is already implemented, an adaptation, a direct copy, or deferred; smallest before/after case; permission and source-provenance checks; cost/latency/completion result; fallback and rollback.
