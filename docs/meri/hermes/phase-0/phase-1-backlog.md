# Phase 1 backlog — dependency-ordered, with acceptance criteria and revised estimates

Prepared September 19, 2026 from the Phase 0 evidence (`checks-report.md`, `capability-ledger.md`, `data-inventory.md`). Owners are roles. Estimates are elapsed working days for the stated staffing and are **provisional**: they assume the Phase 0 code is the starting point and that the two unresolved product decisions below are made before the phase starts.

## Decisions Phase 1 needs from the product owner (not invented here)

1. **Model credential shape**: platform OpenAI key shared by workers vs a budget-capped key per tenant/scope (plan §14 recommends narrow budgets). Default in Phase 0: platform key via `custom` provider.
2. **Warm capacity and idle grace**: how long a private scope worker stays up after a turn (drives cost and the background-review completion rule).
3. **Designated internal test identities** (two, separate private scopes) for the deployed pilot; fixtures were used in Phase 0.
4. **Approval retention window** for native worker approvals (`approvals.timeout`, default 300 s) and whether the pilot allows any guarded terminal command at all.

## Revised estimates

- **Phase 1 (runtime foundation + interactions, tickets 1–7, 11, 19):** ~25 working days with two backend/platform engineers and one frontend engineer working in parallel → **about 3 calendar weeks**, versus the plan's 5–8 days. The extra work is durable run tables, the provisioning service, arm64 images and the UI surfaces that Phase 0 proved are required (clarification, approvals, reconnect).
- **Phase 2 (data/memory/connectors, tickets 6, 8–10, 17):** ~19 working days → **about 3 weeks** for the same team; the audit's missing actor/client checks add roughly a week over the plan.
- **Full-experience scope (2A, 2B, 5, 5A, 6):** Phase 0 evidence supports estimating 2B (skills/persona/learning: tickets 13–15) at ~10 days and 5 (proactive: ticket 18 + templates) at ~8 days. **2A remains "estimate after the catalog spike"** — 340 uncovered business models across 12 schemas make it the largest item; a realistic range after the spike is 6–10 weeks with data owners' participation. **5A** (persistent specialists, detached delegation, media, rollback) needs the Bot Mode / delegation empirical tests listed in the ledger before an estimate; treat as ≥6 weeks.
- Overall: the earlier 6–10-week pilot range covers Phases 1–2 only. A full-parity target is realistically **a quarter or more**, gated by 2A's inventory outcome.

## Measured resource recommendations (see `measurements.md`)

Start the worker class at 1 vCPU / 2 GiB as planned; the image is 3.96 GB, so plan for image pull time in cold-start budgets (local cold start includes bundled-skill seeding on first boot). Reserve a larger class only for browser tasks; Phase 0 did not exercise the browser.
