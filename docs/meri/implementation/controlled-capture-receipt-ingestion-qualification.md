# Controlled signed capture receipt ingestion

The collector previously discarded the signed terminal receipt, while its generic JSON redaction changed numeric token observations and invalidated any saved signature. Controlled collection now compares the terminal envelope with the authorized assistant-message metadata envelope, verifies the actual core signature against a separately supplied in-memory policy, and stores the receipt through a dedicated privacy-validating path. A structural comparison tolerates JSONB object-key order but preserves every value and array order. The writer rereads the actual artifact through the existing hardened reader and verifies its canonical digest and signature.

Only UNIT_FIXTURE_NOT_LIVE callers can use this path. Neither configuration nor the receipt supplies an expected policy. Missing policy or service identity prevents signed-artifact writes. Transport binds the supplied policy to the observed actor, tenant, client, conversation, case and run. Receipt fixture fields must match that policy, but this is not independent fixture-owner proof. Missing current-access, fixture receipt/identity, immutable build and raw source/tool/effect/usage owners remain explicit. A valid signature or producer COMPLETE status never becomes acceptance PASS; diagnostics remain NOT_RUN. The acceptance verifier is unchanged.

The generic redaction, JSON writer and artifact LIVE guard are byte-identical to the prior implementation. A five-line readBytes method delegates to the existing hardened owned-file reader. The receipt-specific path validates numeric usage observations, preserves explicit unknown states, rejects detected credentials or known secrets anywhere in strings/keys, and refuses invalid data rather than changing signed bytes. The trusted signing secret is also included in ordinary exchange redaction. Source version and locator links no longer fall back to configured values.

Canonical verification lazily loads the real built core receipt module. Build @capiro/shared and @capiro/meriv2-core before running signed-diagnostic tests; ordinary missing-policy and closed-LIVE paths do not depend on that output. No substitute HMAC implementation or injected verifier exists.

Controlled tests exercise actual HTTP/SSE/message readback and artifact bytes, reordered keys and arrays, missing/tampered/expired receipts, independent policy/fixture mismatches, malformed usage, secret text/keys, post-terminal/duplicate frames and withdrawn readback authorization. Tests preserve all three closed LIVE gates and the no-retry submission contract. Evidence is saved under C:/dev/cap-meri-foundation-evidence/controlled-receipt-*. Independent review and final gate details are recorded in the external qualification artifact.

The initial Qwen implementation was stopped after direct source inspection found undefined filesystem variables, over-escaped credential patterns and an incorrect costKind schema. Its output and actual exit 1 are retained. Codex completed the bounded repair under the existing user exception and retained separate Hermes/Kimi review.

This change does not implement external policy or fixture owner binding, source joins, complete effect coverage, approved release proof, actual live capture, deployment, or full File01 acceptance. No environment, tenant, database, routing or production model setting is changed.
