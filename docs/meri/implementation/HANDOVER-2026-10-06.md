## 5. The current blocker: private producer inputs (next work)

**Symptom:** `Research run failed: The research report includes private producer inputs without a current authorization adapter.` The same report was also held by the enforce-mode auditor (`D4b`, authorization/appropriation conflation; `packages/meriv2-core/src/grounding/auditor.ts`).

**Rule:** `certifyResearchProducerInputs` (`apps/api/src/meri/meri-report-provenance.ts`, called from `apps/api/src/meri/meri-v3-research-runner.ts` about line 486) marks the producer input `unsupported_private_inputs` when any of these is non-zero:
- handoff summary present
- handoff attachments
- assistant handoff turns
- inherited citations, unavailable or omitted
- context-packet items (`auth.governedContext.contextPacket.items.length`)
- ledger entries without a durable receipt

Publication refuses that mode (`apps/api/src/meri/meri-research.service.ts` about line 3836). Any client-scoped run carries context-packet items, so every client research run, and therefore every Stage 2 job, is refused.

**Existing read-time re-check to extend:** `assertCurrentResearchReportSourcesAuthorized` in `apps/api/src/meri/meri-research-replay-authorization.ts`. It already:
- re-checks the client wall and the originating conversation (owned, not archived, same client);
- re-checks the client-context hash;
- re-executes the owner read of every receipted tool source;
- runs at publication and on every read: `getSession`, Word and HTML export, `authorizeModelContext`.

Reports are readable only by their author (`userId: ctx.userId` on every path); verify that again before relying on it.

**Approved design (Neo, 2026-10-06), to implement:**

1. At publication, record in the report provenance a manifest of the private inputs actually used, without bodies:
   - context-packet items: `id`, `type`, `scope`, authority, and a version or content hash from the item's canonical owner;
   - handoff message ids and the summary hash;
   - attachment ids and content hashes;
   - inherited citation source ids.
2. At every read, re-check each recorded input against its canonical owner. Fail closed and withhold the body with `RESEARCH_REPORT_BODY_WITHHELD` if any input is missing, changed, outside the client wall, or no longer visible to the reader. Examples of owners: memory governance status and wall, client profile hash, attachment row and hash, conversation message ownership.
3. Replace `unsupported_private_inputs` with a covered mode only when every category has an adapter. Keep refusing categories that have none. Ledger entries without a receipt probably stay refused; make the tools that produce them receipted instead.
4. Log the per-category counts when publication is refused. Today the refusal does not say which category tripped; add this first so the live check can confirm the adapter's coverage.
5. Specs: one per category, covering pass, revoked, changed and missing. Then one API roll, then the research check on the QA client.

### 5.1 Survey findings (completed 2026-10-06, after this file was first written)

A read-only survey of the Context Plane and the research producer path answered the questions above. Line numbers are as of main `83a2a183f`; re-read before editing.

**A second blocker sits behind the private-input rule.** Even with every private-input count at zero, a governed client-scoped run fails publication on the client-context hash:
- The governed factory replaces `clientContext` with `governed.prompt` (`governed-meri-research.factory.ts:71-78`), so the certificate hashes the whole Context Plane prompt (runner about `:499`, `meri-report-provenance.ts:73-75`).
- That prompt contains the per-compile random `CONTEXT_PACKET_ID` (`meri-context-plane.service.ts:1166`).
- The publication and read check compares against `sha256(canonicalClientContext(client))` (`meri-research-replay-authorization.ts:566-575`), so it can never match. It throws "A research producer input version changed".
- Existing tests pass `clientContext: null` and never exercise this path.
- Fix it with the adapter: governed runs drop the `clientContextSha256` comparison, and the per-input re-checks below replace it.

**What a fresh client-scoped run actually trips** (new conversation, QA client with approved memories, research as the first action):
- **Zero:** handoff summary, attachments, assistant turns, all inherited counts. The handoff is captured before the topic message is inserted (`meri-research.service.ts:536` vs `:573`). Any earlier chat reply in the conversation makes `assistantHandoffTurns` at least 1.
- **Almost certainly non-zero: `unreceiptedLedgerEntryCount`.**
  - The orchestrator seeds one `context_plane` ledger entry whenever `governedContext.evidence.records` is non-empty (`meriv3-context-evidence.ts:30-70`). The client's own `clients` row alone makes it non-empty.
  - Tools without a read-outcome classifier get no durable receipt: `get_pe_budget_timeline`, `get_program_element`, `get_certification_status`, and the federal and public search tools (`packages/shared/src/meri-read-outcome.ts:796-836`). `search_public_web` is always `partial`.
- **Likely non-zero: `contextPacketItemCount`** (firm-identity is required; client-steering is required for client scope).

**Context-packet items are only `memory_items` steering rows.**
- Types (`contract.ts:42-59`):
  - `firm-soul`, `firm-compass` → firm-identity
  - `playbook` → firm-playbook
  - `user-voice`, `user-profile` → user-voice
  - `client-soul`, `client-compass` → client-steering
  - `client-people` → client-people
- `id` is always `memory_items.id`.
- Packets persist in `context_packet` (`schema.prisma:2921-3004`). `items_jsonb` holds v2 items with `scope`, `clientId`, `ownerUserId`, `status`, `contentHash`, `sourceContentHash`, `sourceVersion`, `approvedAt`; bodies are never stored.
- The report already stores `contextPacketId` (`meri-research.service.ts:3866`).
- Research items are always `selection: 'automatic'`.
- Clients, contacts, strategies and approved memories arrive separately, as Retrieval V2 evidence records (`clients.id`, `engagement_contacts.id`, `strategy:<id>`, `context_document:<id>`, `memory_items.id`, and `steering:<memoryItemId>`).

**Functions to reuse for the read-time re-check:**
- `filterGovernedMemory` (`packages/meriv2-core/src/memory/governance.ts:405-463`), the governed recall predicate, plus `includeCanonicalGovernedMemoryRow` / `canonicalMemoryEligibilitySql` (`retrieval/adapters/governed-memory-eligibility.helpers.ts:17,67`).
- `clientMemoryAllowed` (`memory-wall.helpers.ts:109`), the ethical wall.
- `MeriToolsService.readGovernedMemorySource(ctx, {memoryItemId, clientId?})` (`meri-tools.service.ts:3403`), plus `memoryProof` and `currentOwnerResultAuthorizesReplay('search_memory', …)` for version and hash comparison.
- `MeriContextPlaneService.securityEnvelope(ctx).authorizedClientIds` (`meri-context-plane.service.ts:400-427`) for clients and contacts.
- `EngagementService.extractAttachmentText(ctx, id, {clientId, contextSourceOnly})` (`engagement.service.ts:7715`) for documents.
- `getResearchEvidence` (`meri-research-evidence.helpers.ts:71`) for handoff attachments.
- Nothing re-validates a compiled packet against current state today.

**Recommended adapter (fits the approved design in section 5):**
- Add `producerInputMode: 'governed_inputs'`.
- Record a manifest of ids and hashes only in private session and artifact metadata, hashed into `producerInputSha256`. Never put it in `publicResearchReportMetadata`.
- Re-check it inside the `load()` transaction of `assertCurrentResearchReportSourcesAuthorized`, which already runs before and after the owner calls.

| Category | Record at publication | Re-check at read |
| --- | --- | --- |
| Packet items | `packetId`, `packet_hash`; per item `{memoryItemId, type, scope, clientId, ownerUserId, contentHash, sourceVersion}` (readable from `context_packet.items_jsonb`) | Load the `memory_items` row, apply `filterGovernedMemory` with live `clientMemoryAllowed` and the owner check, compare version and hash; withhold if missing |
| `context_plane` evidence | Per record `{domain, sourceRecordId, contentHash/sourceVersion, updatedAt}` | `institutional_knowledge` and `steering:*`: governed memory read plus `memoryProof`. `clients`, `contacts`, `strategies_work`: row exists, client in `authorizedClientIds`, `updatedAt` unchanged |
| Inherited document citations | Admitted citation ids plus `contentHash` | Extract a per-citation `reauthorize()` from `MeriConversationEvidenceService.load`. That service runs once per producer run today, and only for `read_client_documents` citations |
| Handoff attachments | ids plus `contentSha256` (already in the snapshot) | Re-run `getResearchEvidence` and compare hashes |
| Assistant turns and summary | Message ids and body hashes | No durable source receipts exist, so keep these fail-closed, or stop sending assistant prose and the summary into the producer input |
| Unreceipted tool calls | Tool name plus error flag | Error and blocked results carry no content and can be excluded. PE, program-element and public-web tools need a classifier and owner proof (`classifyApiToolReadOutcome`, `PUBLIC_RESEARCH_SOURCE_TOOLS`, `SUPPORTED_OWNER_TOOLS`, `remainingSourceFamilyProof`) or an explicit public non-private class |

## 8. Hazards learned this session (add to the deployment plan's §0.2 list)

- The pnpm store at `C:\Users\neoma\AppData\Local\pnpm\store\v3` is corrupted. Fresh worktrees install with `--store-dir <private dir>`.
- Python heredocs mangle `\b` and `\n` in regexes. Write patch scripts with the Write tool and pass literal newlines as `chr(10)`.
