## Failure and recovery

- Before merge: stop, retain the last known-good running task, and fix the PR without touching AWS.
- After merge but before/without any runtime change: leave the pinned ECS task alone; fix-forward a build-only workflow. Do **not** blindly revert to the old workflow because it automatically pushes mutable `:latest` and calls ECS. Investigate any unexpected workflow deployment with task digest/ALB evidence and use the separately approved immutable rollback procedure only if an application rollout actually occurred.
- A migration compatibility issue belongs to a separately authorized disposable fresh+upgrade rehearsal and reviewed promotion plan, not to this workflow-only release.
