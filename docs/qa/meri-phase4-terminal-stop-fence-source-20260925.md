# Phase 4 terminal-after-Stop source fence (2026-09-25)

This source-only package narrows one Phase 4 race; it is not a release or full Stop/effect fence. The worker-progress package already refuses nonterminal progress after a committed Stop. This package makes `completed` terminal compare-and-set refuse a non-null Stop marker or `cancelling` status in both Postgres and in-memory stores. A Stop-first worker completion is finalized as cancelled/aborted (or expired when that reason was committed) from durable pre-Stop output, without publishing the worker's completed receipt, success output, or public terminal usage frame. Actual reported usage is retained on the run for accounting. A completion that commits first wins; a later Stop cannot rewrite it.

The worker terminal receipt is staged until the winning finalization transaction, alongside the run transition, assistant message and final `run.status` event. The normal consumer and takeover status-reconciliation paths pass the exact consumer lease fence through terminal compare-and-set and event append; a taken-over old consumer exits without publishing. Explicit Stop and revocation finalizers remain intentionally unfenced by a consumer lease. The new `requestStopIfLive` repository operation commits the Stop marker and public cancelling event under one run-row lock/transaction (one synchronous in-memory block), so cancelling cannot arrive after final done. `requestStop` uses the freshly returned Hermes run ID for best-effort worker stop, not a stale caller snapshot.

Focused in-memory, migrated-Postgres repository, and adapter race regressions were authored for Stop-first, completion-first, expiry, status-poll completion, takeover-terminal, Stop event ordering and stale worker ID. `git diff --check` and independent static review found no remaining P1/P2 in this narrow slice. **None of the new specs, typechecks, builds, or migrations has run under the user's RAM hold.** This is not package acceptance, deployment evidence or live QA.

Still open: Stop during uncertain/in-flight worker admission can leave a late accepted Hermes run active; broker mutations already in progress and S3 publication are not fenced by this run-row change; terminal metering can race an independent revocation finalizer; precommit direct in-process subscribe hints are not a committed event API (production `watch()` re-reads committed rows); runtime/catalog permission parity, pinned image and `https://os.capiro.ai` final QA remain. No broad Phase 4 activation is authorized by this source slice.
