# Dormant result-observer async safety (source only)

Ten existing Phase 2 opt-in read-result wrappers shared a callback failure mode: they caught a synchronous observation throw, but an async callback rejected after the wrapper returned could become an unhandled rejection. `notifyMeriResultObserver` now invokes observation after the successful legacy call, catches synchronous throws, and attaches a rejection handler to any returned Promise without awaiting it. A pending observer cannot delay the legacy result. The wrappers preserve their original public `void` callback signatures, which also accept existing expression-bodied callbacks; there is no active dispatch or model-visible response change. The separately committed CRS observer remains unchanged.

Focused helper and representative wrapper regressions are authored for synchronous throw, rejected and never-settling Promises, expression-bodied callbacks, exact legacy result identity, and unchanged rejection identity when the legacy call fails. Static review and `git diff --check` found no remaining P1/P2 in this narrow slice. **Jest and typecheck/build were not run** under the user resource hold. This is not Phase 2 runtime-envelope or factual-coverage acceptance.
