## Operational boundaries

Visual transcription uses provider capability through the existing completion transport; it adds no custom reasoning engine. It requires a configured OpenAI model accepting PDF input. Requests have `store: false`, no provider retries, a 30-second timeout, one selected page, a 20 MiB original-file limit and a 5 MiB selected-page limit. The bounded in-memory cache is keyed by tenant, document hash, page and model; current access and credential checks precede cache access. Transcription is explicitly identified as provider-generated extraction, and material quotations and figures need comparison with the original.

The fallback runs only when native page text is empty. A page with a text footer and scanned main content can therefore still be incomplete; native text extraction does not establish full image or diagram coverage. Existing historical zero-text documents are labeled honestly; this change does not bulk reindex or modify them.

No production records were altered to validate these repairs. Remaining live release gates include a known revoked-memory/ethical-wall fixture, request-correlated cancellation timestamps, forced provider-effort fallback, a stored hearing transcript with later chunks, export inspection, and a measured government-affairs/provider quality comparison. These tests do not establish complete access to every data source or ChatGPT/Hermes quality parity.
