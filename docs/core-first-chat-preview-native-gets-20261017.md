# Core first-chat preview GET authority and held rollout

**Status: source correction and focused tests complete; image and activation held.** This packet records the correction before the three proposed browser GET forwards can become public. It does not change AWS, start the held service, approve a Clerk pairing, or activate Meri. The existing [GET routing packet](core-first-chat-get-routing-packet-20261017.md) and pinned PR78 source `bcdd689956e1aff3fa316103e75ec60ebe024fda` are the routing baseline. Its acceptance alternative for ordinary GET authority is withdrawn for this preview: the three GETs must receive the native-session and current-visibility policy used by Core's first-chat authority POSTs.

## Why PR48 cannot serve the GETs as pinned

The currently qualified Core API image is PR48 source `6542f5b089656b6d255465edd464d06c2a0b408f`, digest `sha256:722a483259ebb5e9162b9294c26895bafa890fcfee45dc927ff1d2ec35fa071b`, with task `RELEASE_SHA` set to that source. Core's ordinary `GET /api/me`, `GET /api/clients`, and `GET /api/clients/:id` enter the ordinary tenant middleware. That path can provision or rebind a user, repair a membership, and update `lastSeenAt`. It does not impose the authority POST's online native Clerk `sid` recheck. The ordinary client list accepts `includeArchived=true`; direct client detail can return an archived same-tenant record. The reviewed frontend preview gateway currently sends a `capiro` template token to these GETs. The native `/identity`, `/membership`, and `/context` POST checks do not transfer authority to another request.

### Isolated source implementation

The source branch `feat/core-preview-native-gets-20261017` makes this correction preview-scoped rather than changing ordinary production callers. `apps/api/src/config/config.schema.ts` parses `PREVIEW_NATIVE_GETS_ENABLED` only as literal `true`/`false` and defaults false. The shared `preview-native-read-mode.ts` requires both that flag and the fixed Host `first-chat-preview.app-dev.capiro.ai`. For these read routes, preview Host with the flag false and flag true with any other Host return unavailable. Its early route matcher also includes `HEAD`, which Express can dispatch to a GET handler, and checks Express's parsed `req.path` as well as the raw path so an absolute-form request target cannot skip early native authority while reaching the controller. The ALB proposal still forwards **GET only**. This is a routing boundary, not an authorization grant; the future preview task must explicitly set `PREVIEW_NATIVE_GETS_ENABLED=true`.

The newly added early branch in **`apps/api/src/tenant/tenant-context.middleware.ts`** runs before ordinary tenant resolution. It verifies the native Clerk bearer and online active `sid`/`sub`/`exp` session before its first local database read. It rejects impersonation, resolves only an existing user, active membership and active tenant against the token's tenant/org/slug claims, and records request-keyed authority provenance. This branch contains no user creation, identity rebind, membership repair or `lastSeenAt` update. Its placement matters: a controller-only check would run after the ordinary middleware's possible writes. This is a narrow edit to a protected shared authentication path whose source header requires explicit Neo change control. The delegated source correction received independent read-only review; focused ordinary-route regressions are recorded below. Deployment still requires its own approval.

`PreviewNativeReadService` then calls the canonical `ApplicationMembershipService.read` before and after the response-producing operation, with a bounded request control. It requires the same active actor/tenant/role and stable membership revision and visible client roster at response release. The `UsersController.me` preview branch uses that owner around its existing read. The `ClientsController` preview branches call separate `ClientsService` reads limited by tenant, the current visible client IDs, and nonarchived status; direct detail returns the same absent response for foreign, hidden, archived or nonexistent IDs. A preview `includeArchived` request other than explicit `false` is refused. Ordinary non-preview controller paths retain their existing service calls. The preview branches set `Cache-Control: no-store`; focused source tests cover the existing response DTO delegation and ordinary-path regression; live response and latency qualification remain held.

Independent source review counted **five online Clerk session reads and six membership snapshots per successful preview GET**, across the early middleware check and the two complete canonical membership reads. Those repeated checks protect currentness; they also make live latency, Clerk rate limits, bounded request deadlines and failure behavior a qualification gate before routing traffic. No production latency or rate-limit measurement exists in this packet. Do not remove checks merely to satisfy a latency target without a separately reviewed equivalent authority proof.

The task-owned source checkout ran `pnpm -C apps/api exec jest --runInBand --detectOpenHandles --no-coverage` on the preview, loopback Node HTTP/Express, and adjacent existing users, module, tenant middleware and config specs: **10 suites, 170/170 tests passed**. These cover session refusal before local DB access, no writes on preview reads, hidden and archived clients, changed visibility during I/O, exact flag/Host handling, `HEAD`, parsed-path/absolute-form targets, and ordinary tenant middleware behavior. The real HTTP spec confirms that Express dispatches the absolute-form GET to `/api/me` and the early native branch handles it. A scoped imported-graph `tsc --noEmit` covering all changed API source and specs exited **0 with zero diagnostics**. The initial sandbox-only TypeScript attempt could not read several task-owned frozen dependency files; the exact scoped run passed with approved read access and no dependency or source rewrite. An independent source reviewer accepted the scoped design after identifying and resolving the `HEAD` and absolute-form bypasses; this is source and test evidence, not live Clerk, image or latency qualification. The bundled Prisma client used for the tests came from another task-owned checkout with the same exact Prisma schema hash and version after upstream binary download was blocked; no database was contacted.

The frontend owner must change only these Core preview read calls to native `session.getToken()` and qualify that exact source. Native tokens are already used for Meri history and the Core authority POSTs; the bootstrap `capiro` template path remains a separate contract. A code-only Core correction will not work with the pinned frontend gateway's template bearer. The private same-Clerk-application publishable/secret-key pairing, active native `sid`/member/client proof, and approved corrected frontend source remain separate gates; domain and secret ARN metadata alone are insufficient.
