## Concrete authority boundary

Proposed private command: `POST /internal/objective-workload-authority/decisions`, closed request described by `workload-authority.types.ts`; 4 KiB maximum JSON body. A separately authenticated named service principal and Core-owned stored/current facts enter through distinct adapters, never body-supplied actor/tenant/client headers. The opaque delegation UUID alone authorizes nothing. Initial audience/operation pairs:

| Audience | Operation |
|---|---|
| `capiro:objective-strategy-generation:v1` | `objective.strategy.draft` |
| `capiro:objective-planner-materialization:v1` | `objective.plan.prepare` |

No assistant/edit/document, general Planner mutation, activation or outreach capability is implied. A future transport adapter must authenticate a configured named workload identity, check its audience allowlist and load the exact original native actor/membership/tenant/client/Objective/revision/intent/attempt bindings. Planner facts additionally bind original/current Strategy ID, saved StrategyVersion ID+digest, generation publication receipt and grouping digest; any mismatch fails closed. `attemptId` here names a Core-stored delegated attempt; the consuming job's actual claim UUID/attempt/lease remains an additional final-transaction fence, not a guarantee supplied by this evaluator. Existing INTERNAL_SERVICE_SECRET possession and browser application-authority receipts cannot substitute for this adapter. No verifier/issuer is asserted to exist yet.

Concrete future port: `WorkloadIdentityVerifier.verifyTransport(request): Promise<{serviceId, allowedAudiences, identityRevision, validUntilMs, recheckCurrent()}>`, with evidence minted only by that adapter and retained request-locally, never parsed from JSON. Recommended source implementation is a narrow OIDC workload verifier with one configured issuer/trust store, exact audience and issuer-qualified subject-to-service mapping, RS256/ES256 allowlist, no token-selected JWKS URL, credential lifetime at most5 minutes and at most30 seconds authentication clock skew (no grace added to DB effect deadlines). Generation worker and Planner continuation receive separate service-to-audience mappings. This is a recommendation, not a claim an issuer exists: configured issuer/subject ownership and key custody require explicit deployment/security allocation before the adapter can be enabled. No exchange, signing key, token persistence, Clerk session extension or Meri0011 reuse is permitted. All source work in this branch stops before this port's implementation.

Candidate online response is closed `{schemaVersion:1,decisionId,delegationRef,audience,operation,phase,attemptId,runId,requestFingerprint,resultRef,resultHash,authorityRevision,checkedAt,validUntil,absoluteExpiresAt}`; UUID/hash/ref bounds match the pure request types and dates are server UTC. It contains no reusable token and consumers must not treat it as offline final-write permission.400 is invalid syntax,403 uniformly unavailable identity/delegation/scope/current authority,503 unavailable authoritative dependency; no foreign-reference existence detail. Recommended adapter work bound is2 seconds for configured identity lookup and a separate short5-second local decision transaction; no HTTP/JWKS lookup while DB locks are held. No retry may allocate a new operation identity after an unknown result.

Recommended bounds: trusted database clock only; each decision at most15 minutes; fixed absolute ceiling confirmedAt+24 hours; no original worker expiry extension. Dispatch requires no pre-existing run, so unknown ACK must reconcile rather than mint another run. Resume/read/persist bind the original run and immutable expiry. `retained_result_read` can recover the exact persisted terminal result after worker expiry or attempt reclamation, still under fresh current authority and the delegation ceiling; it never permits effects or renews a worker. Result lookup binds attempt/run/request fingerprint/resultRef/resultHash; public failure is uniformly unavailable, with internal safe reason codes only. ## Canonical association proposal

New logical table `client_objective_canonical_plans`, one row keyed `(tenant_id,client_id,objective_id)`, with stable UUID binding ID and positive CAS `binding_version`. This limits only the generated canonical association, not manual Strategies/projects, multiple groups or shared task membership. Retain stable canonical Strategy/project IDs for routine versions. Explicit replacement increments that binding's epoch and records immutable previous-epoch lineage; never silently adopt the latest historical job or first duplicate. `PROPOSED-ASSOCIATION.schema.json` defines the logical row/publication groups, not a SQL migration.

The proposed row covers initial/routine application. A future explicit replacement keeps its newly reserved IDs in a separate pending candidate and does not advance the current epoch/targets/applied pointers before accepted publication. Its eventual single transaction advances the epoch and preserves old publication history. No replacement command or its pending-candidate storage is allocated in this first pure slice.

Required logical columns: binding ID/version/epoch, tenant/client/Objective scope, latest requested intent/revision ID+version, canonical Strategy ID and project ID reserved durably before model dispatch, Strategy-applied source revision ID+version/exact StrategyVersion ID+digest/receipt ID, Planner-applied source revision ID+version/exact accepted StrategyVersion ID+digest/materialization receipt ID, and created/updated DB times. Reserved IDs do not imply that output rows exist; public locators remain unbound/redacted until actual publication. Each applied pointer is null as a complete group until its publication commits. A server-owned trusted applicationTarget pin (binding ID, epoch, expected CAS version and reserved canonical IDs) must enter the typed request/fingerprint before dispatch; candidate draft basis=null is not that binding. Meri must not choose or mint these application IDs. Final write checks the same target pin locally; pure policy alone does not perform this CAS. Immutable subordinate publication history retains prior source/version/result/receipt bindings and output IDs. Meri retains typed result bytes; Core stores only correlated references/digests, not a second output store or scheduler.

SQL must enforce Objective/revision scope and version, positive CAS versions and publication-group coherence. Cross-schema `sp_*` FK/grant feasibility and exact new Core migration are allocation gates; no SQL is authored here. Future source allocations: Core `clients/objectives/objective-canonical-plan.{ts,service.ts,spec.ts}` and explicit Prisma/migration; Strategy generation completion owner for atomic association CAS; existing Planner materializer owner for atomic canonical-project/task correspondence. No production shared writer is claimed by this proposal.

Current Objective revision, requested ready revision, Strategy-applied revision and Planner-applied revision are separate. Editing an Objective to Draft does not relabel existing outputs. Reconfirmation creates an intent/proposal; human-edited output conflicts stop in review-required state until a reviewed merge policy exists. A newer request or model result does not advance applied pointers. Old in-flight attempts cannot replace a newer requested binding. Human edits, completed tasks, manual additions and regrouping remain intact.

If the current Objective no longer matches a requested ready revision, its automatic stages project superseded/source-changed even if a model is still finishing or an old pending row remains. Retain the original immutable requested/applied records and current output availability; do not label stale work as eligible pending/running. Runtime custody status may be observed separately but cannot make that application stage current.

## Composite read proposal

Candidate `GET /clients/:clientId/objectives/:objectiveId/plan`; no new write endpoint. `PROPOSED-COMPOSITE.schema.json` is a closed review schema, not an exported application contract. Core's current Objective/client/role admission runs before discovery; Strategy/project visibility is independently rechecked through their actual owners. Read in a bounded local snapshot; `observedAt` is as-of, not a remote atomicity guarantee. `projectionDigest` is a digest of the public projection, not a monotonic sequence; `bindingVersion` is the canonical CAS version only, not job-progress ordering.

Stage and output availability are independent. Requested/applied revision groups and exact operation receipt IDs prevent a newly pending request from relabelling an old plan. No association means unbound, not proof that no historical/manual outputs exist. Redact IDs/digests of unavailable outputs while retaining authorized Objective-level progress. Empty manual Strategy remains supported; `no_actionable_work` is a truthful notice, not a fabricated task. Node-scoped operations require a currently valid target. Prepared-with-issues is distinct from a clean applied plan; neither means activation/execution.

Project permission does not confer Strategy permission. An authorized available project keeps its own navigable project ID even when Strategy lineage is unreadable; `sourceLineageAvailability=unavailable` and both source StrategyVersion ID/digest are null. Available lineage requires independent current Strategy/version authorization. Unbound/unavailable project locators have no project or lineage IDs. This preserves accessible project navigation without revealing protected identifiers.

### Exhaustive application-stage matrix

Every stage is about the current requested intent, not an older applied pointer. `requestedIntentId` and each applied intent ID accompany their independent revisions, so deliberate regeneration of the same Objective revision remains distinguishable. UUID means a real stored identity; null never means an invented placeholder. These shape constraints are encoded in the proposal schema and are necessary but not sufficient for source authority.

| State | attemptId | receiptId | failureCode |
|---|---|---|---|
| not_recorded | null | null | null |
| pending | null | null | null, runtime_authority_unconnected, authority_unavailable or dependency_unavailable |
| running | UUID | null | null |
| needs_information | UUID | UUID | input_required |
| review_required | UUID | UUID | human_edit_conflict or invalid_result |
| applied | UUID | UUID | null |
| prepared_with_issues (Planner only) | UUID | UUID | null; at least one issue |
| failed | UUID or null (failed before claim) | UUID | invalid_result, dependency_unavailable, deadline_expired or authority_unavailable |
| cancelled | UUID or null | UUID | null |
| superseded | UUID or null | UUID or null | source_changed |
| outcome_unconfirmed | UUID or null | null | outcome_unconfirmed |

A nonnull stage receipt must be an immutable Core application-stage receipt matching ALL of: requested intent ID; requested revision ID+version; Objective/client/tenant scope; this generation/Planner operation; current association ID+epoch (or an explicitly pre-association event with null association); exact attempt identity when present; and the stated stage outcome. Historical raw Meri/job/materialization receipts cannot fill the field by matching only source version. For applied/prepared states, the receipt must also identify the exact corresponding applied publication, intent and reserved target. An older applied pointer remains separately labelled with its original intent/revision while a new stage is pending/running/failed. Superseded with receipt=null is an as-of source-change observation, not a fabricated durable transition. Missing evidence for a purported completed operation becomes outcome_unconfirmed; GET never silently retries a write.

The source observer also validates runtime/model custody states separately: Meri COMPLETED cannot stand in for Core APPLIED. Digest and bindingVersion do not order stage progress; frontend request-generation handling discards stale observations and resets on intent/source changes, without an invented monotonic progress field.

Future materialization retains canonical defaults: private/list/on_track project; todo/unassigned/priority-none/nonrecurring tasks. Do not repurpose on_hold as a draft state, add rules, trigger outreach or activate an external workflow. One default editable group is convenience, not a project/task cap. Only actionable saved nodes create tasks; risks/decisions/gates remain linked context unless existing typed semantics say actionable. Archived exclusions and unsupported/cyclic dependencies remain explicit; required invalid references/cycles reject before writes. A canonical prepared-plan receipt must retain original group/node/task lineage while current human regrouping uses the same IDs.

Normative semantic checks beyond JSON shape: requested.version<=Objective.version; each applied.version<=requested.version; planApplied.version<=strategyApplied.version; same revision version must have the same immutable revision ID; a newer generation can coexist with an older applied plan but cannot relabel it; an applied stage must correspond to the requested source and exact checked publication receipt; available/archived output locators must match that publication's saved IDs/version/digest; unavailable/unbound locators redact all IDs/digests and issues[].sourceNodeId must be null when that Strategy/source identity is unavailable; absent association permits a newly pending intent but no canonical applied pointer; plan publication must bind an existing generation publication in the same binding epoch and canonical Strategy, while an older plan may remain applied after a newer Strategy publication; epoch1 has previousEpoch=null and replacement epochN referencesN-1. Reject a plan applied to a future revision or a foreign-epoch generation receipt even when its JSON shape is valid. Stable root IDs within an epoch and human edit expected-version fences are persistence constraints, not JSON-schema proof. Existing actor-private job/materialization receipts are never relabelled as cross-actor public receipts; the new Core projection requires separately allocated minimal publication references under current authority.

404 covers absent/unauthorized Objective uniformly;503 covers unavailable authoritative dependencies or a response exceeding a reviewed1 MiB bound. GET never claims zero prior writes on missing receipts. A known operation whose receipt cannot be confirmed uses `outcome_unconfirmed`, never retries a write automatically. Mutation409/422 behavior stays with existing commands; this GET adds no mutation. All issues are included or the read fails explicitly; no truncation/task cap. Historical paging is a separate future read contract, not an omitted array silently called complete.
