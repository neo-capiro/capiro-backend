# Meri Promptfoo offline contract (initial, not an accepted live-model baseline)

Scope: a no-network, no-database, no-model Meri regression **mechanism and grader calibration** harness. Do not claim that its success validates live Meri answers, actual model-selected tools, actual retrieval or real conversation memory. The broader release gate needs a separately approved non-production endpoint, authenticated fixture tenant, model-graded rubrics, and full conversation/tool traces. Existing source fixtures are synthetic.

Version: `meri-offline-v1`; immutable pre-change repository SHA `81c7c9c58a4fc3c1e34ab9714614882d74a60c9d`; government-affairs fixture version `2026-09-06.1`. CLI version verified `promptfoo 0.123.1`, Python `3.14.7`. The existing base gate has 11/11 core mechanism cases and 6/6 offline government-affairs reference-answer checks. Do not write an accepted Promptfoo baseline from these checks.

Reproducibility: `suite-contract.json` freezes exact scenario IDs, threshold, fixture version, and SHA-256 of the fixture source. Each runner record contains the actual checkout HEAD; the provider binds each result to SHA-256 of the config, scorer, provider, runner, and source fixture. `verify_report.py` requires the HEAD and all per-result input hashes to match current files, and records the report and contract hashes. HEAD alone is not a worktree snapshot after commit. The initial source commit is not an accepted model-quality baseline. Reports live outside the repository; only transient result files use ignored `.artifacts/` scratch.

Wire interface: Promptfoo config supplies `context.vars` with `caseId`, optional synthetic `request`, `firstRequest`, `selectedClientId`, and scenario expectations (`expectedRecipeTool`, `expectedSubjectScope`, `expectedTargetHint`, `expectedWithinDays`, domains/tools, active-client count, and first-/second-turn recipe/scope/target). JS provider `runtime/provider.cjs` calls actual source through a child `node --import tsx runtime/runner.mjs` from `packages/meriv2-core` cwd, sends vars as JSON via stdin, returns `{output: JSON.stringify(record), metadata:{measurement:record.measurement}}`. Spawn without a shell and with a bounded timeout; an explicit environment allowlist excludes arbitrary DB/cloud/model credentials and Node startup hooks. The real first-turn plan supplies the prior target to the real second-turn planner; expected values never become hidden planner input. Reject unknown case IDs and child failures (no echo/fake answer fallback).

Record JSON after the provider adds file provenance, schemaVersion=1: `{schemaVersion, datasetVersion:'meri-offline-v1', caseId, measurement, result?, answer?, sources?, requiredSourceIds?, expect?, plan?, turns?, grade?, provenance:{gitSha, fixtureVersion, model:'none', inputSha256:{config, scorer, provider, runner, ga_fixture}}}`. Keep absent metrics absent or null; NEVER synthesize actual tool-call trace, model response, retrieval execution, conversation persistence, or semantic faithfulness. `result` contains the ACTUAL `{pass, detail, results?}` from an imported core case; `grade` contains the ACTUAL `gradeGovernmentAffairsAnswer` result; `answer` in GA scenarios is explicitly the HUMAN-WRITTEN fixture `referenceAnswer`, not a Meri response; `sources` are fixture sources. `plan` is the actual `classifyMeriRetrievalIntent` -> `buildMeriRetrievalPlan` output. `turns` contains actual sequential planner results, not persisted conversation. Store only sanitized fixture data in reports.

Required modes and IDs: `core/<case.id>` for all eleven cases from `packages/meriv2-core/test/evals/run-evals.ts` (import each actual exported case; never import `run-evals.ts`, which runs/persists on import); `ga/<fixture.id>` for all six `GOVERNMENT_AFFAIRS_FIXTURES` in `apps/api/src/meri/evals/government-affairs-fixtures.ts`; five `plan/*` scenarios exercising portfolio changes, bounded named external-company lookup, named-entity mailbox history, comprehensive federal-market research, ordinary selected-client lookup; two `sequence/*` scenarios exercising prior entity carried into explicit portfolio overlap and prior entity cleared for unrelated/client follow-up; `calibration/bad-citation` appends `[999]` to a synthetic human reference and must be rejected by the ACTUAL GA grader, `calibration/tenant-leak` runs the existing cross-tenant seeded negative case and must be rejected by the ACTUAL mechanism. For `plan/*` and `sequence/*`, runner accepts only fixture text in vars and calls the real pure planner; score expectations live exclusively in the Promptfoo tests, not the runner. All case IDs are enumerated in config/suite-contract; verify exactly that set in the report.

Python Promptfoo assertion `get_assert(output, context)` returns a GradingResult dict `{pass, score, reason}` and fails closed for missing/malformed record, mismatched id/mode, missing evidence, failed core/GA mechanism or incorrect actual planner plan. For GA independently check required/forbidden strings and citations against supplied source IDs, and label measured scores **citation validity and fixture coverage only** (not semantic faithfulness). Planner tests assert recipe, scope, target, time window, two active and one inactive **synthetic** roster entries, required domains and recommended/forbidden tools. Sequence tests assert first-turn target and second-turn target, recipe, and scope; two pure planner calls do not demonstrate conversation persistence. Calibrations pass only when the real checks reject them for the expected reason. Negative Python/Node tests exercise false-positive grades, fabricated citations, tenant-leak calibration, stale report SHA, and environment isolation. No reference answer should be mislabeled live-model quality.

Run Promptfoo as documented in `README.md`, with `--no-cache --no-share --no-write`, disabled telemetry/remote generation, and explicit removal of provider credentials. Store JSON/HTML/JUnit and summary under `C:/dev/cap-meri-promptfoo-evidence/` or another directory outside the worktree. Require Promptfoo exit 0, 26 exact unique IDs, all per-case Python assertions at threshold 1.0, zero errors/model tokens, and verifier exit 0. Check both aggregate stats and per-row scores; a zero CLI exit without the verifier is insufficient. No accepted baseline exists yet, so do not overwrite one.

Safety: no live API, DB, user secrets, real tenants, AWS, model calls, high-impact actions, or production auth bypass. A reference-answer fixture is calibration data, never a generated answer. No UI files change, so visual QA not applicable.
