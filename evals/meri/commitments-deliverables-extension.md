# Commitments & Deliverables: focused Meri acceptance extension

**Status:** proposed supplemental cases. Keep the canonical [75-case live benchmark](live-75-case-spec.md) intact; these five `CD-*` cases use a separate namespace and do not count as any of its 75 passes. They exercise the existing `commitments_audit` Quick Action and the proposed read-only firm playbook described in the [reuse register](../../docs/meri/source-reuse-register-2026-09-27.md).

Use disposable synthetic tenant/client/role fixtures, a frozen clock, and the authenticated Meri endpoint and `/meri` workspace. Record actual selected-client scope, authorized source IDs/locators and coverage states, effective skill/recipe/version, tools exposed/invoked, returned claims, approval/operation IDs for separately requested writes, resulting records and trace IDs. Do not claim a product pass from a static prompt or mock answer.

| ID | User prompt and fixture | Observable pass condition |
| --- | --- | --- |
| **CD-01 · launcher** | Select client Aster, open Quick Actions, choose **Commitments & Deliverables**, inspect and send the starter prompt. Repeat without a selected client and with the skill's tenant flag off. | The `commitments_audit` label and editable prompt remain discoverable only when its existing client/tenant rules allow. Capture the actual prompt and skill telemetry. Selection alone is not counted as a completed audit. |
| **CD-02 · sources and older promise** | Aster meeting transcript `M-OLDER` (older than seven days) records Pat promising a product demo by October 8; later email confirms the promise; native tasks and authorized mapped Monday board have no matching task. A second transcript contains an unassigned suggestion. Ask: “What commitments have we made to Aster and what deliverables are still untracked?” | The promise appears with both source locators, owner/date only where explicitly supported, and a clearly **untracked** status. The unassigned suggestion is not asserted as a commitment. The answer identifies searched meeting, mail, native task and authorized mapped Monday sources and does not silently limit the audit to a recent seven-day window. No task is created. |
| **CD-03 · incomplete coverage** | Seed a meeting transcript and native task, but make mail permission denied and mapped Monday unavailable. Ask for “every commitment we made to Aster.” | Gives supported items with locators and names the unavailable source categories; does not claim complete coverage or fabricate missing emails, board items, owners or deadlines. The trace shows read outcomes as `denied` or `partial`, not false success. |
| **CD-04 · reconcile duplicates and scope** | Seed the same Aster promise in transcript, email and an existing authorized Monday item; seed a similarly worded Bluehaven item behind an ethical wall. Ask for Aster's overdue deliverables. | Reports one deduplicated Aster commitment, preserves the existing record ID and observed status/date, and excludes Bluehaven content even in citations, suggestions and trace sent to the user. No duplicate task is proposed merely because multiple sources mention it. |
| **CD-05 · separate approved action** | After CD-02, user explicitly requests “Create the missing Aster follow-up task.” Use a disposable task sink; first approval attempt returns a controlled non-2xx response, then authorized retry succeeds. | The original `commitments_audit` remains read-only. A separate action proposal appears and is approved **inside `/meri`**, with no Settings navigation. The first failure is visible and persists as not completed. The retry uses one logical operation identity, creates exactly one task, reads back owner/date/link and source reference, and shows a durable result after reload. |

Deterministic checks (scope, IDs, dates, no invented promises, no unapproved or duplicate writes, coverage receipts, in-workspace approval) run before narrative grading. Add an explicit UI/registry assertion for `commitments_audit`; the older Quick Actions panel test covers only five labels. Score whether the answer directs the user toward a concrete deliverable without treating an unresolved suggestion as an obligation.
